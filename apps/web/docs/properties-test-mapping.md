# 속성 편집기: 원본 테스트와의 대응

작성: 2026-11-10 20:36 KST. `PORTING.md`의 "테스트 매핑"에 이을 표다.

대상은 원본의 속성 값 편집에 관한 테스트 파일이다: `webapp/src/properties/**/*.test.tsx` 11개, `webapp/src/components/propertyValueElement.test.tsx`, `webapp/src/components/personSelector.test.tsx`, `webapp/src/components/cardDetail/cardDetailProperties.test.tsx`, `webapp/src/widgets/propertyMenu.test.tsx`. 모두 77케이스다. `webapp/src/widgets`에는 `editable`, `valueSelector`, `label`, `switch`의 테스트 파일이 없다(그 동작은 위 파일들이 속성 편집기를 통해 본다).

새 테스트는 `tests/ui/properties/`에 종류마다 한 파일이다(vitest, Testing Library, jsdom). 스냅샷은 쓰지 않았다. 원본이 스냅샷으로만 본 상태는, 그 케이스가 가리키는 상태(값이 있을 때, 비었을 때, 읽기 전용일 때 무엇이 보이는가)를 단언으로 적은 새 케이스에 대응시켰다.

## 상태의 뜻

| 상태                   | 뜻                                                         | 건수 |
| ---------------------- | ---------------------------------------------------------- | ---: |
| 대응                   | 원본의 상호작용 케이스를 같은 조작과 같은 결과로 옮겼다    |   27 |
| 대응(동작 다름)        | 같은 조작을 옮겼지만 결과가 원본과 다르다(이유를 적었다)   |   12 |
| 대응(단언)             | 원본은 스냅샷뿐이다. 같은 상태를 새 케이스가 단언으로 본다 |   19 |
| 옮기지 않음: 없앤 기능 | 새 앱에 없는 기능이다                                      |    2 |
| 옮기지 않음: 범위 밖   | 속성 값의 편집기가 아니거나 API·상태 모듈이 있어야 한다    |   17 |
| 합계                   |                                                            |   77 |

스냅샷뿐이라서 대응시킬 것이 없는 케이스는 없었다. 마크업에 묶여 옮기지 못한 케이스도 없었다(원본이 `.Editable`, `.octo-propertyvalue` 같은 클래스로 찾던 요소는 새 테스트가 역할과 이름으로 찾는다).
