## 제안서의 질문별로

- **Q1 (A: 서랍).** 좁은 단계에서 위쪽 막대의 ☰가 서랍을 연다. 바깥 누르기, 보드 고르기, Escape, 닫기 단추, 뒤로 가기로 닫힌다. `AppShell.svelte`.
- **Q2 (가: 전환 시트와 팔레트).** W5라서 만들지 않았다. 지금은 나(서랍 안의 검색 칸)만 있다. W5에서 `Sidebar.svelte`의 검색 칸 자리와 띠에 "보드 찾기"를 붙이면 된다.
- **Q18 (경계 값).** 틀은 `page.stage`와 `sidebarShape`만 본다. 값은 `src/styles/app.css` 한 곳이다. 위쪽 막대는 칸의 컨테이너 변형(`@columns/pane:`, `@header/pane:`)을 쓴다. 1200px 창에서 사이드바를 접으면 설명이 나타나는 것을 테스트한다(창이 아니라 칸을 본다).
- **Q19·Q29 (중간 단계는 띠).** 56px의 띠와, 펼치면 띠 위로 겹쳐 뜨는 서랍. 보드를 밀어내지 않는다(테스트가 칸의 상자가 그대로인 것을 본다). `SidebarStrip.svelte`.
- **Q20 (낮은 화면은 좁음).** `page.stage`가 답하는 대로다. 1000×420이 좁은 단계가 되는 것을 테스트한다.
- **Q21 (뒤로 가기).** 서랍과 설정 대화상자가 `closeOnBack`을 쓴다. 서랍에서 보드를 고르면 라우터가 서랍의 칸을 새 주소로 바꾸고, "뒤로"는 이전 보드로 간다(테스트). 메뉴의 시트는 공용 `BottomSheet`가 한다.
- **Q22 (hover).** 보드와 카테고리의 "…"는 `can-hover:`에서만 숨고, 줄을 가리키거나 줄 안에 초점이 있거나 메뉴가 열려 있으면 보인다.
- **Q23 (크기).** 모든 줄과 단추가 `roomy:`에서 `min-h-touch`/`size-touch`다. 입력 칸(검색, 카테고리 이름)은 `roomy:text-base`. 스위치는 줄 전체가 `label`이라 44px다.
- **Q25·Q36 (안전 영역, 가).** 페이지(`#app`)가 위·좌·우를 비우고 틀은 그 안에 있다. 틀의 높이는 `100dvh`에서 위쪽 값을 뺀 것이다. 화면 전체에 겹치는 서랍만 바탕을 왼쪽 끝까지 칠하고 내용을 `--safe-left`·`--safe-top`만큼 들인다. 띠와 사이드바의 발은 `--safe-bottom`, 개발용 표시는 오른쪽·아래, 설정 대화상자는 네 방향을 따로 쓴다. 좌우를 한 값으로 준 곳은 없다(테스트: 오른쪽만 84px, 그다음 왼쪽 30px·위 24px·아래 34px).
- **Q27 (가림).** 토큰 `scrim`을 그대로 쓴다.
- **Q33·Q34 (창 크기가 바뀔 때, 가).** 목록이 한 요소라 스크롤과 검색어가 남는다. 열린 서랍은 좁음↔중간에서 열린 채이고, 사이드바가 고정되는 순간 닫히며, 다시 좁아져도 저절로 나오지 않는다(테스트). 메뉴가 시트↔드롭다운으로 바뀌는 것은 공용 `ActionMenu`의 일이다(부품이 갈린다).

## 생성 UI에 관해

- `ui/sidebar`는 틀도 안쪽 부품도 쓰지 않았다. 줄은 링크와 단추에 클래스를 직접 적었다(전환 너비와 `showOnHover`가 너비 기준이라서. 제안서의 "생성 UI에서 눈에 띈 것").
- `ui/dialog`의 닫기 단추(28px, 오른쪽 위에 고정)는 설정 대화상자에서 끄고(`showCloseButton={false}`) 머리글 줄에 `IconButton`을 두었다. 넉넉한 밀도에서 44px가 되고, 화면을 채울 때 안전 영역 밑으로 들어가지 않는다.
- `ui/switch`는 줄 전체를 `label`로 감쌌다(18×32px짜리라서).
- 생성 UI의 파일은 고치지 않았다.

## 그림 (`docs/screens/shell/`)

다섯 화면 × 세 단계 × 밝은·어두운 화면, 30장이다(CSS 픽셀 크기, 합계 1.6 MB). 파일 이름은 `<화면>-<compact|medium|expanded>-<light|dark>.png`. 모든 그림에 개발용 표시가 켜져 있어 창·페이지·칸의 너비가 찍혀 있다.

| 화면       | 무엇                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| `frame`    | 열자마자의 모습: 좁음은 ☰만, 중간은 띠, 넓음은 고정 사이드바            |
| `sidebar`  | 좁음·중간은 열린 서랍, 넓음은 검색어("plan")로 좁힌 고정 사이드바        |
| `menu`     | 보드의 "…" 메뉴: 좁음은 바닥 시트, 중간·넓음은 드롭다운                  |
| `readonly` | 읽기 전용 보드("읽기 전용" 표시, 제목이 글자). 넓음은 사이드바를 접은 띠 |
| `settings` | 설정 대화상자: 좁음은 화면 전체, 중간·넓음은 가운데                      |

다시 찍는 명령(`apps/web`에서, 먼저 `build`): `FVOCI_SCREENS=1 FVOCI_E2E_PORT=<포트> pnpm exec playwright test e2e/shell.spec.ts -g pictures`.

- **보드 아이콘이 빈 네모로 찍혀 있다.** 이 기기(헤드리스 Chromium)에 이모지 글꼴이 없어서다(`fc-list`에 색 글꼴이 0개). "✔"처럼 글꼴에 있는 것만 보인다. 실제 기기에서는 이모지가 나올 것이나 확인하지 못했다.
- 어두운 화면에서 직접 열어 본 것(2026-11-10 23:50 KST): `frame-expanded-dark`, `menu-compact-dark`, `menu-expanded-dark`, `readonly-expanded-dark`, `sidebar-medium-dark`, `settings-medium-dark`, `settings-compact-dark`. 글자는 모두 읽히고 겹치거나 잘린 곳은 없었다. 띠의 "지금 보드"는 바탕과 테두리로, 설정의 고른 답은 더 어두운 바탕으로 구분된다.
