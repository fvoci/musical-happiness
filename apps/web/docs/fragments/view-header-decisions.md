## 스스로 정한 것

형식: 무엇을 / 왜 그 안을 / 다른 안 / 바꾸려면.

### 배치

1. **전체 한 줄의 도구 단추(속성, 그룹화 기준, 필터, 정렬)는 낱말만 있고 아이콘이 없다.** / 칸 1024px(1280px 창)에서 도구와 검색 칸이 약 600px를 쓰고, 아이콘 넷(88px)이 뷰 탭 하나의 자리다. 아이콘을 두면 영어 이름의 뷰 넷 가운데 지금 탭 하나만 온전히 보였다. / 목업처럼 아이콘과 낱말을 함께 두기. 992–1200px쯤에서만 아이콘만 두기(경계 값이 하나 더 생긴다). / `ViewHeader.svelte`의 `tool` 스니펫에 주석으로 적은 한 줄(`{#if row}` 안에 `<ToolIcon data-icon="inline-start" />`).
2. **탭이 다 들어가지 않으면 지금 뷰가 아닌 탭이 4rem까지 줄고(이름은 말줄임, `title`에 온 이름), 그래도 모자라면 탭 줄이 가로로 스크롤된다. 지금 뷰의 탭은 줄지 않고 보이는 자리로 스크롤된다.** / 뷰가 많아도 한 줄을 지키고, 지금 어느 뷰인지는 늘 읽힌다. / 넘치는 탭을 "더 보기" 메뉴로 접기. / `ViewTabs.svelte`의 탭 클래스(`min-w-16 shrink`, `shrink-0`).
3. **검색 칸의 너비는 10rem(전체 한 줄).** / 탭의 자리를 남기려고. / 초점이 가면 넓어지는 칸. / `ViewHeader.svelte`의 `w-40`.
4. **접힌 줄에서 단추가 없는 도구(속성, 그룹화 기준, 정렬)는 요소를 지우지 않고 "…" 위에 보이지 않게(`invisible absolute`) 겹쳐 둔다.** / 같은 요소라서 칸의 너비가 바뀌어도 열려 있던 팝오버가 닫히지 않고, 접힌 줄에서는 "…" 아래에, 펴진 줄에서는 자기 단추 아래에 붙는다. 팝오버가 닫히면 초점은 "…"로 보낸다. / 접힌 줄용 겉을 따로 두기(칸이 바뀔 때 닫힌다). `PickerSurface`에 기준 요소를 따로 받는 인자를 더하기(공용 부품을 고쳐야 한다). / `ViewHeader.svelte`의 상수 `ASIDE`와 `closedAside`.
5. **둥근 "새로 만들기" 단추는 보드 페이지 상자의 오른쪽 16px, 아래 `1rem + --safe-bottom + --keyboard`, 56px, `z-20`.** 전체 한 줄의 단추와는 다른 요소다(초점은 옮겨 가지 않는다). / 머리글이 검색 칸을 덮는 기준 상자(`relative`)라서 같은 요소를 두 자리에 둘 수 없다. 오른쪽 안전 영역은 `#app`이 이미 비운다. / 머리글을 기준 상자로 쓰지 않고 한 요소로 두기. / `ViewHeader.svelte`의 맨 아래 `Button`.

### 뷰

6. **접힌 줄의 뷰 목록에는 뷰들 아래에 "보드 뷰 추가", "표 뷰 추가", "갤러리 뷰 추가" 세 줄이 바로 있다.** / 한 번 덜 누른다. / "뷰 추가" 한 줄이 종류 목록을 여는 두 단계(목업). / `ViewSwitcher.svelte`의 `actions`.
7. **새 보드 뷰는 `groupById`에 첫 선택 속성을 적고 열(`visibleOptionIds`)도 채운다.** / 원본은 비워 두고 그릴 때 첫 선택 속성으로 대신한다. 적어 두면 뷰가 그 대신하기에 기대지 않는다. 그룹을 바꿀 때와 같은 함수를 쓴다. / 원본처럼 비워 두기. / `view-fields.ts`의 `newViewFields`.
8. **이름 바꾸기는 "…" 자리에 뜨는 작은 겉(팝오버, 좁은 단계는 시트)의 입력 칸이다. Enter, "저장", 바깥 누르기, 시트의 "완료"는 저장하고 Esc는 버린다. 앞뒤 공백은 뗀다. 빈 이름도 저장된다(탭에는 "(제목 없는 뷰)").** / 두 모양에서 같은 방식이고 시트에서도 된다. / 탭의 글자를 그 자리에서 고치기(원본. 접힌 줄에는 탭이 없다). 대화상자. / `ViewMenu.svelte`의 `setRenameOpen`, `renameKeys`.
9. **마지막 뷰의 "뷰 삭제"는 숨기지 않고 꺼 둔다.** / 메뉴의 모양이 보드마다 달라지지 않는다. / 원본처럼 숨기기. / `ViewMenu.svelte`의 `disabled`.
10. **뷰를 지운 뒤 어느 뷰를 보일지는 머리글이 정하지 않는다.** 페이지(`src/app/BoardPage.svelte`)의 "주소의 뷰가 없으면 첫 뷰로 바꿔 넣는다"는 규칙이 한다. / 지운 뷰의 주소가 방문 기록에 남지 않는다. / 지우기 전에 다른 뷰로 먼저 옮기기(원본). / `ViewMenu.svelte`의 `onConfirm`.
11. **복제한 뷰의 이름은 `{이름} copy`(한국어 `{이름} 사본`)이고 복제본을 바로 보인다.** / 원본과 같다(원본은 영어 고정). / — / 메시지 `viewheader_copy_title`.
12. **캘린더 뷰의 머리글에는 정렬과 그룹화 기준이 없고, 원본의 "표시 기준"(날짜 속성 고르기)도 없다.** 뷰 추가에도 캘린더가 없다. / 캘린더 뷰는 범위 밖이다. / — / `view-fields.ts`의 `ADDABLE_VIEW_TYPES`, `sortOffered`, `groupingOf`.

### 속성, 그룹

13. **속성 목록: 보드의 속성 전부, 갤러리는 맨 위에 "제목", 표가 아닌 뷰는 맨 아래에 "댓글 및 설명"(`__badges`).** 켠 속성은 목록 끝에 붙는다. / 원본과 같다. / — / `view-fields.ts`의 `propertyToggles`, `withPropertyVisible`.
14. **그룹을 바꾸면 열은 값 없는 열(`''`)이 맨 앞, 그 뒤로 선택지 순서이고, 숨긴 열과 접은 열(`collapsedOptionIds`)을 모두 비운다.** / 값 없는 열이 앞인 것은 뷰가 열을 적지 않았을 때 로직(`logic/group.ts`)이 그리는 순서와 같다. 접은 열도 옛 속성의 선택지라 함께 비웠다. / 값 없는 열을 맨 뒤에(내장 템플릿이 그렇다). / `view-fields.ts`의 `groupingFields`.
15. **표의 "그룹 해제"는 `groupById`를 빈 문자열로 쓴다.** / 내장 템플릿과 원본이 그렇게 쓴다. 필드를 지우는 것보다 와이어에서 뜻이 분명하다. / 필드를 지우기. / `groupingFields`.
16. **그룹 기준이 없는 보드 뷰의 단추에는 첫 선택 속성의 이름이 적힌다.** / 그려지는 것과 같게(원본). / "없음". / `view-fields.ts`의 `groupProperty`.

### 필터

17. **새 조건은 아직 조건이 없는 첫 필터 가능 속성에, 그 값 종류의 기본 조건으로, 값 없이 붙는다. 모든 속성에 조건이 있으면 제목에 붙는다.** 값이 없는 조건은 모든 카드를 통과시킨다(체크박스의 "설정"만 바로 걸린다). / 원본과 같되, 원본은 남은 속성이 없으면 "(unknown)" 줄을 만든다. / — / `filter-edit.ts`의 `addClause`.
18. **속성을 바꾸면 값을 비우고, 조건만 바꾸면 값을 남긴다.** / 원본과 같다. "비어 있음"으로 갔다 돌아와도 고른 값이 있다. / — / `setClauseProperty`, `setClauseCondition`.
19. **글 조건의 값은 입력마다가 아니라 Enter, 칸을 떠날 때, 칸이 화면에서 사라질 때 저장한다.** / 글자마다 저장하면 글자마다 실행 취소 한 단계와 쓰기 한 번이 생긴다. 사라질 때 저장하는 것은 시트가 팝오버로 바뀌며 칸이 다시 지어질 때 치던 글을 잃지 않으려는 것이다. / 멈춘 뒤 0.3초에 저장. / `FilterRow.svelte`의 `saveText`.
20. **선택지와 사람의 값은 속성 편집기(`components/properties/kinds/SelectProperty.svelte`, `PersonProperty.svelte`)를 여러 개 고르기로 그대로 쓴다.** / 검색, 칩, "지우기", 시트·팝오버, Q13·Q14의 동작이 이미 있다. / 스위치 목록을 새로 쓰기. / `FilterRow.svelte`.
21. **날짜는 달력에서 하루를 누르면 저장하고 닫힌다. "오늘"(계정의 시간대), "지우기"가 있고 직접 치는 칸은 없다.** / 하나만 고르는 것이라 Q13의 가. / 날짜 속성 편집기처럼 입력 칸도 두기. / `FilterDate.svelte`.
22. **"모두 만족/하나라도 만족"은 조건(중첩 묶음 포함)이 둘 이상일 때만 보인다.** / 하나일 때는 고를 것이 없다. / 늘 보이기. / `FilterEditor.svelte`.
23. **조건 한 줄은 값 칸이 14rem을 요구해서 휴대폰 너비에서는 값이 둘째 줄로 내려가고, 팝오버(32rem)에서는 한 줄이다.** 값이 없는 조건("비어 있음")은 한 줄이다. / 너비에 맡기면 경계 값이 필요 없다. / 좁은 단계에서 늘 두 줄. / `FilterRow.svelte`의 `basis-56`, `FilterEditor.svelte`의 `w-[32rem]`.
24. **필터 단추의 수는 중첩된 묶음 안의 조건까지 센 수다.** / 걸린 조건의 수라서. / 맨 위의 줄 수. / `filter-edit.ts`의 `conditionCount`.

### 정렬

25. **한 속성으로는 한 번만 정렬한다(이미 있는 속성은 "정렬 추가"에 나오지 않는다). 새 줄은 맨 끝에 오름차순으로 붙는다.** / 같은 속성의 두 번째 줄은 뜻이 없다. / — / `sort-edit.ts`.
26. **방향은 "오름차순/내림차순"이 적힌 단추를 눌러 뒤집는다. 줄을 옮기면 초점이 그 줄의 단추를 따라가고(끝에 닿아 꺼지면 반대쪽 단추), 지우면 "정렬 추가"로 간다. 옮긴 결과는 `role="status"`로 알린다.** / 키보드와 화면 낭독기로 순서를 바꿀 수 있게. 끌어서 옮기기는 넣지 않았다. / `Sortable`로 끌기. / `SortEditor.svelte`.
27. **"정렬이 있으면 끌어서 순서를 바꿀 수 없다"는 안내는 보드와 표 뷰에서, 정렬이 하나라도 있을 때만 보인다.** / 지시가 든 것이 그 두 뷰다. / 늘 보이기. / `SortEditor.svelte`의 `dragged`.

### 검색

28. **접힌 줄에서 검색어가 있는 동안에는 줄 전체가 검색 칸이다(덮인 단추는 `inert`). 닫기(왼쪽 화살표)와 Esc가 검색어를 비우고 닫는다. 전체 한 줄에서 Esc는 검색어만 비운다.** 다른 뷰로 가면 닫힌 채로 시작한다. / 검색이 걸려 있는데 칸이 안 보이는 상태를 만들지 않는다. 대신 접힌 줄에서는 검색을 건 채로 필터를 고칠 수 없다. / 검색어를 남기고 돋보기에 표시만 하기. / `ViewHeader.svelte`의 `searchBar`.
29. **검색은 입력마다 바로 걸린다(지연 없음).** / 지시대로. 원본은 0.2초 늦춘다. / — / `bind:value={search}`.

### 그 밖

30. **읽기만 하는 보드는 `board.canEdit` 하나로 가른다.** 뷰 고르기와 검색만 남고 "…"도 없다. 원본은 뷰·속성을 고치는 권한과 카드를 만드는 권한을 따로 보지만 저장소에 그 구분이 없다. / 권한을 새로 판단하지 않는다. / — / `ViewHeader.svelte`의 `canEdit`.
31. **스크린샷은 CSS 픽셀 1배로 찍는다.** / 48장이 5.4MB에서 2.3MB가 된다. / 기기 배율 그대로. / `e2e/view-header.spec.ts`의 `scale: 'css'`.
32. **종단 테스트는 좁은 단계에서 자리 표시 틀의 보드 목록을 치우고 돈다.** / 자리 표시 틀은 412px 화면에서도 256px 목록을 옆에 두어 칸이 156px가 된다. 그런 칸은 실제 기기에 없다. 목록이 서랍인 틀에서는 아무것도 하지 않는다(좁은 단계에서 칸이 페이지보다 100px 넘게 좁을 때만 치운다). / 156px 칸에서 그대로 돌리기. / `e2e/view-header.spec.ts`의 `givePaneItsRoom`.

## 지시에 없던 것

- 필터 편집기가 중첩된 묶음이 있으면 "중첩된 조건 묶음: n개. 그대로 유지되며 여기서는 고칠 수 없습니다"라고 한 줄로 알린다. 고치는 UI는 없다. 알리지 않으면 카드가 왜 걸러지는지 화면에서 알 수 없다.
- 뷰 탭은 Ctrl·⌘·Shift·가운데 단추로 누르면 브라우저에 맡긴다(새 탭으로 열기).
- 정렬 줄을 옮긴 결과를 화면 낭독기에 알린다.

## 창 크기가 바뀔 때 (Q34의 확인)

`e2e/view-header.spec.ts`의 "while the window changes size" 2건으로 확인했다(Chromium, `setViewportSize`).

| 바뀌는 것                       | 열려 있던 것                                                        | 결과                                                                                                                                                         |
| ------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 칸의 너비(전체 한 줄 ↔ 접힌 줄) | 필터 팝오버, 그 안의 글 칸                                          | **그대로 남는다.** 팝오버도 입력 칸도 같은 DOM 요소이고, 치던 글과 초점이 남는다. 팝오버는 필터 단추를 따라간다                                              |
| 같다                            | "…"에서 연 정렬 팝오버                                              | 남는다. 접힌 줄에서는 "…" 아래, 펴지면 "정렬" 단추 아래                                                                                                      |
| 같다                            | 검색어                                                              | 남는다(페이지의 상태). 접히면 줄 전체가 검색 칸이 된다                                                                                                       |
| 같다                            | 뷰 목록(접힌 줄), "+" 메뉴                                          | **닫힌다.** 다른 모양에는 그 단추가 없다                                                                                                                     |
| 페이지의 단계(팝오버 ↔ 시트)    | 필터, 정렬, 속성, 이름 바꾸기                                       | **열린 채로 다시 지어진다.** 열림 상태는 머리글이 들고 있어 남는다. 이름 바꾸기에 치던 글은 겉 밖의 상태라 남고, 필터의 글 조건은 사라지면서 저장되어 남는다 |
| 같다                            | 그 안의 초점과 커서                                                 | **남지 않는다**                                                                                                                                              |
| 같다                            | 필터 안에서 또 열어 둔 것(선택지 목록, 달력, 속성 메뉴)과 그 검색어 | **닫힌다**(확인하지 않았다. 구조가 그렇다)                                                                                                                   |

남지 않는 것을 남기려면 공용 겉(`components/picker-surface/PickerSurface.svelte`, `components/menu/ActionMenu.svelte`)이 두 모양에서 **내용을 한 번만 그려야** 한다. 지금은 `{#if presentation === 'sheet'}`의 두 갈래가 내용 스니펫을 따로 그린다. 모바일 안의 카드(안 A)가 한 것처럼(시트와 대화상자가 같은 프리미티브라 클래스만 바꾼다. `docs/mobile-proposal.md`의 "창 크기가 바뀔 때") 겉을 대화상자 하나로 두고 팝오버 모양일 때의 위치만 스크립트로 잡는 방법이 있다. 머리글 쪽에서 더 할 수 있는 것은 없다.

## 공용으로 내릴 후보

- `lib/logic/filter-conditions.ts`의 `conditionsOf`(값 종류의 조건 목록)를 내보내면 `filter-edit.ts`의 `conditionsFor`가 쓰는 우회("그 종류가 그대로 받아 주는 조건만 고른다")가 필요 없다.
- `view-fields.ts`의 `BADGES_COLUMN_ID`(`__badges`), `DEFAULT_TITLE_COLUMN_WIDTH`(280): 칸반·갤러리·표가 같은 값을 쓴다. `logic/wire.ts`의 `TITLE_COLUMN_ID` 옆이 제자리다.
- `texts.ts`의 `VIEW_ICONS`(뷰 종류의 아이콘): 사이드바가 뷰를 보이게 되면 같이 쓴다.

## 눈에 띈 것 (머리글 밖)

- **`src/app/BoardPage.svelte`: 뷰를 고칠 때마다 검색어가 지워졌다.** "다른 뷰는 검색 없이 시작한다"는 효과가 뷰 객체에 기대고 있었고, 뷰는 고칠 때마다 새 객체다. 뷰의 id에만 기대게 고쳤다(세 줄).
- **실행 취소는 쓰기의 답이 온 뒤에야 등록된다**(`logic/undo.ts`의 `perform`이 `redo`를 기다린 뒤 등록한다). 무엇을 고치고 답이 오기 전(메모리 구현은 40ms)에 실행 취소를 누르면 그 앞의 변경이 취소된다. 종단 테스트는 답을 기다린 뒤 취소한다. 고치지 않았다.
- **`ActionMenu`의 "지금 고른 것"(`checked`)은 체크 아이콘뿐이고 화면 낭독기에는 전해지지 않는다**(`aria-checked`도 `menuitemradio`도 아니다). 뷰 목록, 그룹화 기준, 필터의 속성·조건이 이것을 쓴다. 고치지 않았다.
- **jsdom에서는 팝오버와 드롭다운의 내용이 조금 뒤에 `visibility: hidden`이 된다**(위치를 잡는 코드가 크기 0인 단추를 "화면 밖"으로 본다). 역할과 이름으로 찾는 질의가 이름을 못 찾는다. `tests/ui/view-header/header.test.ts`는 레이블과 글로 찾는다.
