`href` 규칙(`schema.ts`의 `isAllowedHref`, 서버도 같게): 공백과 제어 문자(U+0000–U+0020, U+007F)를 모두 지운 뒤 판단한다. 스킴이 있으면 `http`, `https`, `mailto`만(대소문자 무관). 스킴이 없으면 앱 안의 경로로 보되 `//`로 시작하거나 역슬래시가 들어 있으면 거절한다(브라우저가 바깥 주소로 읽는다). 제어 문자를 지우는 이유는 브라우저가 스킴을 읽기 전에 탭·줄바꿈을 버려서 `java\tscript:`가 통하기 때문이다.

### 저장 형식의 규칙

편집기의 `getJSON()` 결과를 `toStoredDoc`이 한 번 정리해서 보낸다. 서버가 받는 모양은 다음과 같다.

- 노드는 `type`, `attrs`, `content`, `marks`, `text` 다섯 멤버만 갖는다. 그 밖의 멤버가 있으면 거절한다.
- **`null`은 없다.** 값이 없는 속성은 빼고, 속성이 하나도 없으면 `attrs` 자체를 뺀다(예: 언어 없는 코드 블록은 `{"type":"codeBlock","content":[…]}`).
- `marks`는 마크가 있을 때만 있다. 같은 종류가 두 번 올 수 없다. 순서에는 뜻이 없다(편집기는 스키마 순서로 낸다).
- 빈 본문은 `{"type":"doc","content":[{"type":"paragraph"}]}`이다. 권고: 클라이언트가 이것을 `body: null`로 보내고 서버는 NULL로 저장한다. 서버가 둘을 같게 다루기만 하면 된다.
- 한도: 깊이 32(`doc`이 1), 노드 20,000개. 목록 한 단계가 깊이 둘(`bulletList` → `listItem`)을 쓰므로 깊이 32는 목록 중첩 약 14단계다. 템플릿의 최대 깊이는 5다.

예:

```json
{
  "type": "doc",
  "content": [
    {
      "type": "heading",
      "attrs": { "level": 2 },
      "content": [{ "type": "text", "text": "할 일" }]
    },
    {
      "type": "taskList",
      "content": [
        {
          "type": "taskItem",
          "attrs": { "checked": true },
          "content": [{ "type": "paragraph", "content": [{ "type": "text", "text": "번역 검수" }] }]
        }
      ]
    },
    {
      "type": "paragraph",
      "content": [
        { "type": "text", "text": "담당 " },
        { "type": "mention", "attrs": { "userId": "…" } },
        { "type": "text", "text": " 문서는 " },
        {
          "type": "text",
          "text": "여기",
          "marks": [{ "type": "link", "attrs": { "href": "/board/…" } }]
        }
      ]
    },
    { "type": "image", "attrs": { "fileId": "…", "alt": "진행 그래프" } }
  ]
}
```

### 서버 쪽에서 더 볼 것

- **`image.fileId`**: 그 파일이 같은 보드의 것인지(3.7절의 규칙 그대로). 붙여넣기로 남의 `data-file-id`가 든 HTML이 들어오면 편집기는 그 ID를 그대로 싣는다. 걸러 내는 곳은 서버다.
- **`mention.userId`**: 형식만 볼지, 그 보드의 멤버인지까지 볼지 정해야 한다. 편집기는 목록에서 고른 ID만 넣지만 붙여넣기로는 아무 ID나 들어올 수 있다. 화면은 모르는 ID를 ID 그대로 보여 준다.
- **검색**: 본문이 JSON이 되면 지금의 제목 검색처럼 문자열을 바로 찾을 수 없다. `schema.ts`의 `plainText`가 문서에서 글자만 뽑는다(문단마다 한 줄). 서버가 검색용 평문을 따로 둘지는 서버 쪽 판단이다.
- **카드의 할 일 수**: 원본은 마크다운의 체크박스와 checkbox 블록을 세어 카드에 배지를 붙인다. 이제 `taskItem` 노드를 세면 된다(`countTasks`). 클라이언트가 본문을 받아 세면 되므로 서버가 따로 줄 필요는 없다. 다만 목록 화면에서 본문 전체를 받지 않으려면 서버가 세어 주는 편이 낫다.

```ts
  | { ok: true; empty: boolean; fragment: DocumentFragment } // 본문의 블록들. `doc-body` 클래스의 요소 안에 넣는다
  | { ok: false; problems: string[] }; // 검증기가 말한 이유. DOM은 하나도 만들지 않았다
```

```svelte
<!-- src/lib/editor/BodyView.svelte -->
<BodyView {doc} {resolveUser} {taskLabel} class="p-4">
  {#snippet invalid(problems)}표시할 수 없는 본문{/snippet}
  {#snippet empty()}내용 없음{/snippet}
</BodyView>
```

- `doc`은 서버가 준 문서를 JSON에서 읽은 값이다. `null`과 없음은 빈 본문이고 오류가 아니다. 빈 본문의 저장 형식인 "빈 문단 하나"도 빈 본문으로 본다(`empty: true`, 그린 것 없음). 2절의 권고대로 둘을 같게 다룬다.
- 검증(`validateDoc`)에 실패하면 본문의 일부도 그리지 않는다. 무엇을 대신 보일지는 호출부가 정한다(부품에서는 `invalid` 스니펫).
- 부품은 `editor.css`를 스스로 가져오고, 그린 것을 `class="doc-body"`인 `<div>` 안에 넣는다. API나 상태 모듈에 기대지 않는다.
- 표시기와 그것이 가져오는 모듈에는 Tiptap, ProseMirror, marked가 없다. 가져오는 것은 `schema.ts`, `files.ts`, `drawing.ts`뿐이다. 글자는 텍스트 노드로, 속성은 `setAttribute`로만 넣는다. 문자열을 요소로 바꾸는 API(`innerHTML` 등 13가지)가 소스에 나오면 테스트가 실패한다.

그리는 방식에서 정한 것:

- **링크**: 편집기와 같은 `target="_blank"`, `rel="noopener noreferrer nofollow"`(이제 두 쪽이 `drawing.ts`의 한 상수를 쓴다). `href`는 그리는 자리에서 `isAllowedHref`를 다시 통과해야 속성이 된다. 통과하지 못하면 글자만 그린다.
- **이미지**: `src`는 `files.ts`의 `fileUrl(fileId)`. 주소를 풀 수 없으면 편집기처럼 `src` 없이 자리만 잡는다. `loading="lazy"`, `decoding="async"`. `alt`는 문서에 있을 때만 붙는다(편집기와 같다).
- **멘션**: 이름은 `resolveUser`가 준다. 모르면 편집기처럼 ID를 그대로 보인다.
- **할 일**: 진짜 체크 상자다. 상태(`checked`)가 그대로 읽히고, 누르거나 스페이스를 눌러도 바뀌지 않는다(클릭을 되돌린다). `disabled`로 두지 않은 것은 흐리게 그려져 편집기와 달라 보이기 때문이다. 바꿀 수 없다는 것은 `aria-readonly="true"`로 알린다. 접근성 이름은 그 할 일의 첫 문단의 글자이고 `taskLabel`로 문구를 바꾼다.
- **빈 줄**: 빈 문단·제목·코드 블록과, 줄바꿈이나 줄 바꿈 문자로 끝나는 문단에는 편집기와 같은 자리에 `<br>`을 둔다. 브라우저는 빈 마지막 줄에 높이를 주지 않으므로, 이것이 없으면 빈 문단이 사라지고 편집기와 높이가 달라진다.
- **마크의 겹침**: 저장된 마크의 순서에는 뜻이 없으므로 편집기의 순서(`link`, `bold`, `italic`, `strike`, `code`, 바깥부터)로 정렬하고, 이웃한 글자가 바깥쪽 마크를 공유하면 한 요소로 묶는다. 편집기가 그리는 방식 그대로다.

### 하면서 찾은 것 (표시기 밖)

- **편집기가 검증기가 거절하는 문서를 낼 수 있었다(고침, 2026-11-10 20:37 KST).** 굵은 글자 안의 줄바꿈이나 멘션을 HTML로 읽으면(`<strong>a<br>b</strong>`) 편집기는 그 `hardBreak`와 `mention`에도 마크를 붙이고, 검증기는 "글자에만 마크가 온다"며 거절한다. 허용 목록은 그대로 두고 저장 형식으로 정리하는 `toStoredDoc`이 글자가 아닌 노드의 마크를 떼게 했다(글자 없는 노드의 마크는 뜻이 없다). 편집기 안의 상태에는 마크가 남지만 저장되는 문서는 검증을 통과한다. `tests/ui/editor.test.ts`의 "keeps marks off line breaks and mentions inside marked text"가 고정한다.
- **검증기가 객체라면 다 가진 이름을 목록에 있는 것으로 봤다.** `{"type":"constructor"}` 같은 마크가 통과했다(`MARK_SPECS[이름]`이 상속된 멤버를 찾는다). `Object.hasOwn`으로 고쳤다(`schema.ts` 두 줄, `tests/editor/schema-own-names.test.ts` 11건).
- **검증기가 문서 모양이 아닌 값에서 예외를 던졌다(고침, 2026-11-10 20:37 KST).** `marks`가 숫자, `content`에 `null`, `attrs`가 숫자, 속성 이름이 `constructor`인 경우 등이다. 이제 어떤 값에도 예외 없이 문제의 목록으로 답한다(`tests/editor/schema.test.ts`의 "a value that is not shaped like a document" 18건). 마크에 `type`과 `attrs` 밖의 멤버가 있으면 거절하는 것도 이때 더했다(서버 설계 5.7절의 "그 밖의 멤버는 거절"과 같게). `renderBody`의 예외 처리는 그대로 남겨 두었다.

### 확인하지 못한 것

- **화면 낭독기.** 체크 상자의 상태와 `aria-readonly`, 이름이 실제로 어떻게 읽히는지 듣지 못했다. `aria-readonly`를 체크 상자에서 읽어 주지 않는 낭독기가 있을 수 있다.
- **Firefox, Safari, 실제 기기.** Chromium headless만 돌렸다. Firefox에서는 편집기가 경우에 따라 공백으로 끝나는 문단에도 `<br>`을 더한다(ProseMirror의 `requiresGeckoHackNode`). 모양에는 영향이 없을 것으로 보지만 비교하지 못했다.
- **한글 입력기로 넣은 글.** 브라우저 테스트는 글자를 직접 넣었다. 이 기기의 headless 브라우저에는 한글 글꼴이 없어 스크린숏의 한글이 빈 네모로 나온다(두 쪽이 같다).
- **아주 큰 문서를 그리는 시간.** 노드 한도(20,000개)의 문서가 그려지는 것만 확인했다.
- **Storybook 화면.** 빌드한 결과에서 네 이야기가 오류 없이 그려지는 것은 확인했다. 툴바의 테마·글자 크기 전환은 보지 않았다.

### 제품 부품 `BodyEditor.svelte`

약속한 모양 그대로다(`body-editor.ts`의 `BodyEditorProps`). 호출부는 `await import('$lib/editor/BodyEditor.svelte')`로 늦게 받는다. 타입만 필요하면 `body-editor.ts`에서 가져온다(부품을 받지 않고도 이름을 쓸 수 있다).

- **`doc`은 만들어질 때와 `revision`이 오를 때만 읽는다.** `doc`만 바뀌면 쓰던 글이 남는다. `revision`으로 다시 읽는 것은 변경이 아니어서 `onChange`가 불리지 않는다.
- **`onChange`는 저장 형식(`toStoredDoc`)의 문서를, 빈 본문이면 `null`을 준다.**
- **검증에 실패하는 문서는 불러오지 않는다.** 편집기는 비고 읽기 전용이 되며, 상태 줄(`role="status"`)이 그 사실을 알린다. `editable`을 주어도 풀리지 않는다. 이유: 편집기는 모르는 노드를 말없이 버리고 읽으므로, 그 상태에서 한 글자를 고치면 원래 본문이 "고친 추측"으로 덮인다. 더 새 판이 쓴 본문을 옛 클라이언트가 여는 경우가 이것이다.
- **Tiptap이 넣는 스타일시트를 껐다**(`injectCSS: false`). 그 시트의 규칙 13개 가운데 12개를 `editor.css`의 맨 위 블록으로 옮겼다(틈 커서의 `black`은 `--foreground`로. 옛 Firefox용 `::-moz-selection` 하나는 뺐다). 테스트가 페이지에 `style[data-tiptap-style]`이 없는 것을 본다. `editor.css`의 겹쳐 쓴 선택자는 남겼다: 그 옵션 없이 편집기를 만드는 곳(테스트)에서도 모양이 같게.
- **창 크기가 바뀌어도 글·커서·초점이 남는다**(6.5절의 세 테스트가 그대로 통과한다).
- 더한 선택 인자: `label`(글 상자의 접근성 이름. 없으면 "본문"), `toolbar`(스니펫, `{ editor, changes }`를 받는다), `onLoad`(문서를 읽은 뒤 편집기가 저장할 모양을 알린다. 거절했으면 `undefined`). 내보낸 함수는 없다(`storedDoc()`과 `focus()`를 두었다가, 부르는 곳이 없어 2026-11-11에 지웠다).
- 이미지: `uploadImage`가 있으면 붙여넣거나 끌어 놓은 이미지 파일을 넘기고, 식별자가 올 때까지 문서 밖의 자리 표시를 보인다. 없으면 이미지 파일을 받지 않는다.
- 멘션의 이름은 `resolveUser`, 없으면 `users`에서 찾는다. 이름이 나중에 알려지면 화면의 멘션을 고친다(문서에는 여전히 식별자뿐이다).

**서식 도구 모음은 부품에 없다.** `lib/editor`는 `lib/ui`의 버튼을 가져올 수 없는 층이다. 카드 상세 화면은 `toolbar` 스니펫에 자기 버튼을 그려 넘기거나, `lib/components`에 도구 모음 부품을 두어 여러 화면이 같이 쓴다(권장. 이번 일의 범위 밖).

### 이모지

**콜론 규칙**(`emoji-trigger.ts`): 줄에서 마지막 콜론 뒤에 친 것이 이름에 쓸 수 있는 글자뿐이고(모든 문자의 글자·결합 부호·숫자, `_ + -`), **콜론 바로 앞 글자가 ASCII 영문자나 숫자가 아니면** 목록을 연다. `10:30`, `http:`, `note:x`는 걸러지고 `안녕:`, `你好:`, `こんにちは:`, `(:`, 줄의 처음은 열린다. 줄 안의 멘션이나 수식 뒤의 콜론도 열린다. 코드 블록 안에서는 열지 않는다. 테스트: 규칙 자체 38건(`tests/editor/emoji.test.ts`, node), 진짜 편집기에서 목록이 불리는 때(`tests/ui/editor-formulas.test.ts`의 "the list of emoji", jsdom), 브라우저(`spikes/editor/embeds.spec.ts`의 "the list of emoji" 4건과 받는 시점 1건).

### 수식

노드 둘: `inlineMath`(문장 안), `blockMath`(한 줄). 속성은 `latex` 하나(1–4,000자). 화면에서는 원문을 담은 요소 하나다:

```html
<span data-type="inline-math" data-latex="E = mc^2" class="doc-math">E = mc^2</span>
<div data-type="block-math" data-latex="…" class="doc-math">…</div>
```

`renderBody`와 편집기의 노드 뷰가 똑같이 이 요소를 만들고, `embeds.ts`가 KaTeX를 받아 그 안에 그린다. 그리기 전과 그릴 수 없을 때는 원문이 코드 모양으로 보인다. 그릴 수 없으면 원문 뒤에 안내 문구(`role="note"`)가 붙는다. 그리면 `data-state="drawn"`, `role="math"`, `aria-label`(원문)이 붙는다.

**입력**: `$x^2$`(닫는 `$`를 칠 때), 한 줄 전체가 `$$…$$`, 빈 줄에서 `$$`와 공백(그 줄에 블록 수식의 편집 자리가 열린다). `$5 and $10`, `US$5$`, `\$x$`는 글자로 남는다. **고치기**: 수식을 누르거나 선택한 채 Enter. 줄 안의 수식은 상자에 원문과 미리보기가 있고 Enter로 적용, Esc로 취소한다. 블록 수식은 다이어그램처럼 수식 아래에 편집 자리가 열리고, Esc·Ctrl+Enter로 닫을 때 고친 것이 본문의 실행 취소 한 단계로 들어간다. 비우면(닫으면) 수식을 지운다. 입력기 조합 중의 키는 명령으로 보지 않는다.

**한도**. 주 스레드의 동기 호출은 중간에 끊을 수 없다. 그래서 한 수식은 입력과 결과의 크기로 묶고, 수식 사이를 끊는다.

### 다이어그램

언어가 `mermaid`인 코드 블록이다. 표시기와 편집기 모두 그림으로 원문을 대신한다(원문은 숨기되 페이지에 남는다). 편집기에서는 그림을 누르거나 선택한 채 Enter로 그림 아래에 원문을 열어 고친다(`docs/decisions.md`의 29). 그리기 전과 그릴 수 없을 때는 원문이 보이고, 그릴 수 없으면 안내와 라이브러리의 오류 글(글자로)이 붙는다.

원문은 한 사용자가 쓰고 다른 사용자의 화면에서 그려진다. 방어는 네 겹이고, 겹마다 혼자서도 막게 했다(`diagram.ts`의 머리말).

1. **라이브러리가 보기 전**: 원문 20,000자 한도(넘으면 라이브러리를 받지도 않는다). 그림 노드(`@{ img: … }`)의 거절.
2. **라이브러리의 설정**: 아래 표.
3. **잠금을 빠져나온 설정이 있으면 그리지 않는다.** 이 판에서는 빠져나오는 것이 없다(모르는 설정도 라이브러리가 버린다). 다음 판을 위한 덫이다.
4. **그린 SVG를 그대로 넣지 않는다.** `safe-svg.ts`가 따로 만든 문서에서 읽어(아무것도 실행되거나 받아지지 않는다) 허용한 것만 새로 만든다.

**Mermaid에 준 옵션과 근거**(12.3.0. 문서는 저장소 태그 `mermaid@12.3.0`의 `docs/config/usage.md`의 "securityLevel", 패키지의 `dist/config.type.d.ts`. 소스는 `dist/mermaid.core.mjs`의 `renderDiagram`·`parse`, `dist/chunks/mermaid.core/chunk-BG4553SI.mjs`의 `sanitize`와 기본 설정):

| 옵션                      | 값                                                               | 근거                                                                                                                                                                                                                                               |
| ------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `securityLevel`           | `'strict'`                                                       | 아래 "네 수준"                                                                                                                                                                                                                                     |
| `htmlLabels`              | `false`                                                          | 라벨을 `foreignObject` 속의 HTML이 아니라 SVG `<text>`로 그린다(`config.type.d.ts`: 루트의 `htmlLabels`가 종류별 설정보다 앞선다)                                                                                                                  |
| `secure`                  | 라이브러리의 기본 설정에 있는 모든 이름 + 거기 없을 수 있는 11개 | `config.type.d.ts`: "controls which `currentConfig` keys are considered secure and can only be changed via call to `mermaid.initialize`. **네 수준 가운데 왜 `strict`인가.** `usage.md`: `strict`는 "(default) HTML tags in the text are encoded and click functionality is disabled", `antiscript`는 "HTML tags in text are allowed (only script elements are removed) and click functionality is enabled", `loose`는 둘 다 허용, `sandbox`는 "all rendering takes place in a sandboxed iframe. This prevents any JavaScript from running in the context". 실행을 막는 힘만 보면 `sandbox`가 가장 세다. 그러나 소스(`putIntoIFrame`)를 보면 결과가 `<iframe sandbox src="data:text/html;base64,…">` 문자열이다: 이 페이지가 속을 볼 수도, 걸러 낼 수도, 토큰의 색을 줄 수도 없고, 정책이 `data:` 프레임을 허용해야 하며, 프레임 안의 스타일이 바깥 주소를 부르는 것은 `sandbox` 속성이 막지 않는다. `strict`는 걸러 낼 수 있는 SVG 문자열을 주고, 그런 수준 가운데 가장 엄격하다. 그래서 `strict`에 설정 잠금과 걸러 내기를 얹었다.

**라이브러리만으로는 막히지 않던 것**(이 기기에서 직접 돌려 확인했다. `strict`, `htmlLabels: false`, `secure`에 기본 설정 이름 전부를 넣은 상태):

| 원문                                                                                    | 일어난 일                                                                                          | 지금 막는 곳                                              |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `%%{init: {"htmlLabels": true}}%%` + 라벨에 `<img src="https://…">`                     | **그리는 중에 그 주소로 요청이 나갔다.** `htmlLabels`는 기본값이 없어 기본 설정 이름 목록에 없었다 | `secure`에 기본값 없는 설정 11개를 더했다(`ALSO_SECURE`)  |
| 머리말(front matter)의 `config: { htmlLabels: true, securityLevel: loose }` + 같은 라벨 | 같다                                                                                               | 같다                                                      |
| `A@{ img: "https://…" }`(노드를 그림으로)                                               | **그리는 중에 그 주소로 요청이 나갔다**(크기를 재려고 그림을 받는다). 설정과 무관한 문법이다       | 원문 단계의 거절(`fetchesWhileDrawing`), 읽은 뒤의 재확인 |

그리는 동안의 일은 걸러 내기(4)보다 앞서 일어나므로 1과 2가 막아야 한다. 이 셋이 지금은 요청을 내지 않는다는 것을 아래 공격 문자열 테스트가 고정한다.

**걸러 내기가 남기는 것**(`safe-svg.ts`의 목록): 요소 36종(`svg`, `g`, `defs`, `symbol`, `marker`, `clipPath`, `mask`, `pattern`, 두 그라디언트와 `stop`, 도형 7종, `text`·`tspan`·`textPath`, `title`·`desc`, `switch`, `use`, `style`, `filter`와 그 안의 9종). `feImage`, `image`, `script`, `foreignObject`, 애니메이션 요소는 목록에 없다. `<a>`는 벗기고 안의 것은 남긴다. 속성은 이름 목록에 있는 것과 `aria-*`만, `data-`는 `data-look` 하나만. `href`는 `use`·`textPath`·그라디언트·`pattern`에서 `#이름`일 때만. 값에는 허용한 CSS 함수 22가지(`rgb`, `hsl`, `var`, `calc`, 변환 함수들, `drop-shadow`, `brightness`, `url` 등)만 올 수 있고 `url()`은 `url(#이름)`만. `style` 속성은 선언 단위로 걸러 CSSOM으로 넣는다. `<style>`은 규칙 단위로: 선택자가 모두 그림의 식별자로 시작해야 하고, `@keyframes` 밖의 at-규칙은 버리며, 이스케이프(`\`)나 `<`가 든 시트는 통째로 버린다. 깊이 64, 요소 50,000개를 넘는 그림은 받지 않는다. SVG 하나가 아닌 것(프레임, 그림 둘, 그림 밖으로 나온 HTML)은 받지 않는다.

**시간**: 그리기는 한 번에 하나씩 한다. 8초를 넘기면 안내를 보이고 기다리기를 그만둔다. 라이브러리의 배치 계산은 동기라 끊지는 못한다. 일의 크기는 원문 길이와 간선 수(500)로 묶는다.

수식 14가지(브라우저)와 19가지(jsdom): `\href`(주소, `javascript:`, `data:`), `\url`, `\includegraphics`(주소, `data:`), `\htmlClass`·`\htmlId`·`\htmlStyle`·`\htmlData`, `\text`·`\verb`·`\char` 속의 마크업, 색 인자에 끼운 스타일(`\textcolor{red;background:url(…)}`), `\tag` 속의 마크업, 끝없는 매크로와 불어나는 매크로, `\rule{99999em}{99999em}`, 끝없는 공백, 속성을 끝내려는 따옴표. 결과: 링크·그림·`id`·바깥 클래스·`data-` 속성·`position`·배경이 하나도 만들어지지 않는다. `\html…`은 수식 전체가 오류가 되고, `\href`·`\url`·`\includegraphics`는 명령 이름이 오류 색 글자로 그려진다. 페이지가 옆으로 늘어나지 않는다.

### 받는 시점과 크기

- **`elkjs`(ELK 배치 엔진): EPL-2.0 또는 GPL-3.0.** 루트 `deny.toml`의 허용 목록에 없다. 이 판의 Mermaid는 ELK가 기본 배치다. **번들에서 뺐다**: `vite.config.ts`의 별칭이 `elkjs`를 빈 모듈(`no-elk.ts`)로 바꾸고, 설정은 `layout: 'dagre'`로 잠갔다. 빌드에 `elkjs`의 모듈이 0개인 것을 측정 스크립트로 확인했고, 실리면 고지 단계가 빌드를 실패시킨다(그 단계에는 예외가 없다). 설치 검사에는 "설치되지만 실리지 않는다"는 예외(`notShipped`)로 적었다. 스파이크와 Storybook의 빌드는 이 별칭을 쓰지 않는다(그 설정 파일은 이번 일의 것이 아니다). 그 둘은 배포물이 아니고 ELK 코드는 조각으로만 들어가며 실행되지 않는다. **EPL-2.0을 허용 목록에 넣을지는 정책 판단이라 하지 않았다**(넣으면 별칭과 `layout` 한 줄을 지우면 된다).
- **`khroma`(색 함수): `package.json`에 라이선스 필드가 없다.** 패키지 안의 라이선스 파일은 MIT다. 예외 목록의 `stated`에 이름과 라이선스, 파일에 있어야 할 문장을 적었고, 도구가 그 문장을 파일에서 확인한다(설치 검사와 고지 단계 둘 다).
- **`robust-predicates`: Unlicense.** d3를 따라 설치되지만 다이어그램이 쓰지 않아 번들에 없다(고지 단계가 확인한다). `notShipped`에 적었다.

**KaTeX 글꼴**은 OFL-1.1이다. 패키지는 코드의 라이선스(MIT)만 적고, 글꼴의 라이선스는 글꼴 파일의 이름 표에만 있다. `tools/licenses/katex-fonts.ts`가 스타일시트가 가리키는 글꼴 20개 각각에서 "This Font Software is licensed under the SIL Open Font License, Version 1.1."을 확인하고(하나라도 없으면 빌드 실패), 저작권과 예약 이름 12개, 라이선스 본문(SPDX의 `OFL-1.1.txt`, SHA-256 `8eea8287…e9bcfd`)으로 고지를 만든다. KaTeX가 번들에 들어갈 때만 실린다. 측정 빌드의 고지에서 `KaTeX fonts (20 files) 0.19.1 (font) [OFL-1.1]`, `katex 0.19.1 [MIT]`, `khroma 2.1.0 [MIT]`, CLDR 둘 `[Unicode-3.0]`, `dompurify 3.4.17 [(MPL-2.0 OR Apache-2.0)]`(Apache-2.0으로 허용)를 확인했다.

WOFF2만 싣는 방법: KaTeX의 스타일시트는 글꼴마다 WOFF2·WOFF·TTF 세 주소를 적는다. 그대로 가져오면 번들러가 60개를 싣는다. `tools/math/katex-css.ts`가 그 시트에서 WOFF2 주소만 남긴 사본(`src/lib/editor/katex.css`)을 만들고 커밋했다. 설치된 패키지에서 다시 만들어 견주는 테스트가 있다(KaTeX를 올리면 도구를 다시 돌린다).

### 어두운 화면

- **수식**은 글자 색(`currentColor`)으로 그려진다. KaTeX의 스타일시트에 색이 없는 것을 테스트가 본다. 브라우저 테스트가 두 화면에서 수식의 색이 문단의 글자 색과 같은 것을 확인한다.
- **다이어그램**의 색은 토큰에서 읽는다(`diagram.ts`의 `PALETTE`, `SERIES`). 토큰은 oklch라 라이브러리(색 계산에 `khroma`를 쓴다)가 읽지 못하므로, 캔버스에 한 점을 칠하고 그 점을 읽어 `#rrggbb`로 넘긴다. 반투명 토큰은 바탕 위에 칠한다. 읽을 수 없는 브라우저에서는 라이브러리의 `neutral` 테마로 물러난다. 루트 요소의 `class`가 바뀌면(밝기가 바뀌면) 편집기와 표시기의 모든 다이어그램을 다시 그린다. 브라우저 테스트가 노드의 채움이 두 화면 모두에서 `--muted`와 같은 색이고 밝기를 바꾸면 그림이 새로 그려지는 것을 확인한다.
- **대비**(표시기, 예제 `embeds`, 브라우저에서 잰 값): 밝은 화면에서 수식 19.8:1, 노드의 라벨 18.2:1, 선 5.5:1. 어두운 화면에서 19.0:1, 14.5:1, 7.7:1. 테스트는 글자 4.5:1, 선 3:1 이상을 요구한다.
- 스크린샷: `docs/screens/editor/`의 `view-light.png`, `view-dark.png`, `editor-light.png`, `editor-dark.png`(1280×900, 예제 `embeds`). 다시 찍으면 커밋하지 않는 `target/screens/spikes/editor/`에 생긴다(2026-11-11부터). 다시 찍으려면 `FVOCI_EDITOR_SHOTS=1 FVOCI_SPIKES_PORT=<포트> pnpm --filter web run spikes:e2e editor/embeds --project desktop`. 평소의 실행은 찍지 않는다(기기의 글꼴에 달린 산출물이다).

### 편집기와 표시기의 비교에 더한 것

9절의 비교가 새 노드를 담는다.

- **jsdom**(`body-compare.test.ts`): 손으로 만든 문서에 `formulas`(인라인·블록 수식, 문단의 처음과 끝, 제목·목록·인용·할 일 안, 마크 사이, 그릴 수 없는 것)를 더했고, 다이어그램 문서 둘(`WITH_DIAGRAMS`)을 따로 비교한다. 비교한 문서는 78개(템플릿 58, 손으로 만든 17, 다이어그램 2, 스파이크 예제 1. 그 예제도 이제 수식을 담는다), 노드는 17종 모두 한 번 이상이다. 빼는 것에 하나가 늘었고(11. 편집기가 원문 뒤에 두는 다이어그램 그림), 4번이 수식에도 적용된다(문단을 끝내는 수식 뒤의 `<br>`). 수식과 다이어그램은 **그리기 전의 자리**로 비교한다. 그리는 일은 두 쪽이 같은 모듈(`embeds.ts`)을 쓴다.
- **브라우저**(`view.spec.ts`): 예제 `everything`과 `corners`가 이제 수식을 담고, **그려진 수식의 모든 요소**까지 위치·크기·스타일을 비교한다. 빼는 것에 하나가 늘었다: 수식의 MathML 속 `<annotation>`(브라우저가 그리지 않는 요소라 자리가 없다). 다이어그램은 이 비교에 넣지 않는다: 편집기는 원문과 그림을, 표시기는 그림만 보이는 것이 의도다.
- 비교가 찾아낸 것 하나: 선택된 수식의 테두리에 준 모서리 반경이 계산된 스타일의 차이로 잡혔다(외곽선만 남겼다).

### 확인하지 못한 것

- **실제 한글 입력기.** 테스트는 글자를 직접 넣는다. 조합 중에 콜론 목록과 `$…$` 규칙이 어떻게 구는지, 조합 중의 Enter가 목록에서 무엇을 고르는지는 실제 입력기로 봐야 한다. 원문 상자는 조합 중의 키를 명령으로 보지 않게 했지만(`isComposing`) 실제 입력기로 확인하지는 못했다.
- **Firefox, Safari, 실제 모바일 기기.** Chromium headless만 돌렸다. 특히: 입력 규칙의 정규식이 뒤돌아보기(lookbehind)와 유니코드 속성을 쓴다(Safari 16.4 이상). 토큰 색을 읽는 캔버스가 oklch를 받는지(받지 못하면 `neutral` 테마로 물러나게 했지만 그 길을 실제로 타 보지 못했다). 깊은 수식의 배치 시간과 한도(200)는 Chromium에서 잰 것이다. Firefox는 바깥 SVG의 채움(`fill: url(다른 문서#…)`)을 받아 올 수 있는데, 걸러 내기가 `#이름` 밖의 `url()`을 모두 지우므로 영향이 없을 것으로 보지만 돌려 보지 못했다.
- **화면 낭독기.** 수식의 `role="math"`와 `aria-label`(원문), 다이어그램의 이름(종류와 "누르면 고칩니다"), 자동 완성 목록의 `aria-activedescendant`, 줄 안 수식의 원문 상자의 `role="dialog"`가 실제로 어떻게 읽히는지 듣지 못했다. 다이어그램의 접근성 이름은 종류까지다(내용은 숨긴 원문에 있다).
- **엄격한 콘텐츠 보안 정책 아래의 동작.** 정책이 아직 없어 돌려 보지 못했다. 소스로 본 것: 편집기와 수식은 스크립트가 넣는 스타일시트를 쓰지 않는다. 다이어그램은 그린 SVG 안의 `<style>`이 막힌다(색을 잃는다). Mermaid 자신도 그리는 동안 `<style>` 요소를 만든다.
- **Mermaid가 그리는 동안의 페이지.** 라이브러리는 글자 크기를 재려고 실제 페이지 안(화면 밖에 둔 자리)에 그린다. 걸러 내기는 그 뒤의 일이다. 그리는 동안의 요청은 테스트한 공격들에서는 없었지만, 라이브러리의 새 판이 그리는 중에 무엇을 받아 오는 문법을 더하면 테스트에 없는 한 새어 나갈 수 있다. 판을 올릴 때 공격 문자열 테스트를 돌리고 새 문법을 본다. 더 단단한 길은 라이브러리를 자기 정책(`default-src 'none'`)을 가진 별도 문서에서 돌리는 것이다(하지 않았다: 글자 크기를 재려면 앱의 글꼴이 그 문서에도 있어야 한다).
- **다이어그램 종류 전부의 모양.** 스무 종류가 우리 설정에서 그려지는 것은 한 번 확인했다(`foreignObject`는 여정에서만 나오고 그 옆의 `<text>`가 대신 그려진다). 종류마다 토큰 색으로 읽기 좋은지는 흐름도·시퀀스·파이만 눈으로 봤다. dagre 배치로 바꾼 뒤의 모양은 흐름도만 봤다.
- **아주 많은 수식.** 한 본문의 수식 수백 개가 예산(3초) 안에서 어떻게 보이는지 재지 않았다.
- **Storybook.** 이야기(`Editor/Body`의 수식·다이어그램, `Editor/BodyEditor` 여섯)를 더했고 타입 검사와 린트는 통과한다. 빌드해서 열어 보지는 않았다.
