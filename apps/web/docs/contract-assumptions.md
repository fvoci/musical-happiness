# 계약 없이 가정한 것 (서버 세션에 넘기는 문서)

작성: 2026-11-10 23:10 KST. 웹앱 트랙(`fvoci/web`)이 서버의 계약(`contracts/openapi.json`) 없이 화면을 조립하면서, 서버 설계(`hafgufa` 워크트리의 `docs/s6-design.md`)에 **없어서 지어낸 곳**을 모은 것이다. 설계에 있는 것은 그대로 따랐고 여기에 적지 않았다.

화면은 서버를 직접 부르지 않는다. 화면이 쓰는 읽기·쓰기·구독은 `src/lib/state/backend.ts`의 `Backend` 인터페이스 하나이고, 지금은 메모리 구현(`src/lib/state/memory/`)이 꽂혀 있다. 계약이 나오면 그 인터페이스를 서버 호출로 구현해 `src/app/backend.ts`에서 바꿔 끼운다. 아래의 가정이 계약과 다르면 고칠 곳은 대부분 그 구현 하나이고, 인터페이스의 모양까지 바뀌는 경우는 항목에 "인터페이스가 바뀐다"고 적었다.

읽는 법: **가정**은 지금 코드가 그렇게 돼 있다는 뜻이고, **질문**은 서버 세션의 답이 필요한 것이다. 설계의 절 번호는 `s6-design.md`의 것이다.

## 3. 화면이 정한 처리 (서버의 답에 따라 달라질 수 있는 것)

- **낙관적 갱신.** 고치기는 화면에 먼저 보이고, 거절되면 되돌리고 알린다. 한 블록에 쓰기가 진행 중일 때 도착한 판(답과 메시지)은 붙들어 두었다가 마지막 쓰기가 돌아오면 가장 새 것을 적용한다(`src/lib/state/write.ts`).
- **409(본문).** 덮어쓰지 않는다. 카드를 다시 읽어 저장된 본문이 내가 알던 것과 같으면 새 판으로 한 번 다시 보내고, 다르면 두 글을 모두 들고 사용자에게 고르게 한다(`src/lib/state/card.svelte.ts`).
- **실행 취소.** 화면의 일이다. 고치기는 반대 패치를 보내고, 만들기의 취소는 삭제, 삭제의 취소는 복원이다. 그래서 **복원 라우트는 휴지통에 있는 한 언제든 되어야 하고**, 만들기를 다시 실행하면 새 식별자의 것이 생긴다.
- **검색.** 열린 보드의 카드를 화면이 거른다(제목과 속성). 본문은 찾지 않는다(목록에 본문이 없다). 본문 검색은 서버의 `body_text`(5.7)가 생긴 뒤의 일이다.

### 2. 새 노드

| 노드         | 속성                                 | 안에 올 수 있는 것   | 어디에 올 수 있는가                                                                         |
| ------------ | ------------------------------------ | -------------------- | ------------------------------------------------------------------------------------------- |
| `inlineMath` | `latex`: 문자열, **1–4,000자, 필수** | 없음(`content` 없음) | 인라인 자리: `paragraph`, `heading` 안. `text`, `hardBreak`, `mention`과 같은 자리          |
| `blockMath`  | `latex`: 문자열, **1–4,000자, 필수** | 없음(`content` 없음) | 블록 자리: `doc`, `listItem`, `taskItem`, `blockquote` 안. `paragraph`, `image`와 같은 자리 |

- 블록 목록: `paragraph`, `heading`, `bulletList`, `orderedList`, `taskList`, `blockquote`, `codeBlock`, `horizontalRule`, `image`, **`blockMath`**.
- 인라인 목록: `text`, `hardBreak`, `mention`, **`inlineMath`**.
- `codeBlock` 안에는 여전히 `text`만 온다(`inlineMath`는 올 수 없다).
- `listItem`·`taskItem`의 첫 자식은 여전히 `paragraph`다(`blockMath`가 첫 자식일 수 없다).
- 다른 노드처럼 `marks`와 `text` 멤버를 가질 수 없다(`marks`는 `text` 노드에만).
- `latex` 밖의 속성은 거절한다. 그린 결과(HTML, MathML)는 저장하지 않는다. 저장하는 것은 **LaTeX 원문 문자열 하나**뿐이다.
- 이름은 편집기 라이브러리(Tiptap)의 공식 수식 확장이 쓰는 이름 그대로다(`inlineMath`, `blockMath`, 속성 `latex`).

예:

```json
{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [
        { "type": "text", "text": "에너지는 " },
        { "type": "inlineMath", "attrs": { "latex": "E = mc^2" } },
        { "type": "text", "text": " 입니다." }
      ]
    },
    { "type": "blockMath", "attrs": { "latex": "\\int_0^1 x^2 \\, dx = \\frac{1}{3}" } },
    {
      "type": "codeBlock",
      "attrs": { "language": "mermaid" },
      "content": [{ "type": "text", "text": "flowchart LR\n  A --> B" }]
    }
  ]
}
```

#### `latex`의 한도: 무엇을 세는가 (맞춰야 할 것)

웹앱의 검증기는 문자열 길이를 **UTF-16 코드 단위**로 센다(JavaScript의 `length`). 이것은 `latex`만이 아니라 판 1의 모든 길이 한도(`fileId` 100, `alt` 1000, `userId` 100, `href` 2048, `language` 40)에 똑같다. 5.7절은 "자"라고만 적었다. BMP 밖의 글자(이모지, 일부 한자)는 코드 단위 둘이므로, 서버가 유니코드 스칼라 값으로 세면 경계에서 두 구현이 어긋난다.

- **요청**: 서버도 UTF-16 코드 단위로 세거나, 다르게 센다면 알려 달라(웹앱이 맞춘다). 어느 쪽이든 공유 테스트 벡터에 아래 4절의 "BMP 밖의 글자" 경우를 넣어 고정한다.
- `latex`의 내용은 검증하지 않는다(문법, 명령어, 제어 문자 모두). 어떤 문자열이든 길이만 맞으면 받는다. 틀린 수식은 그리는 쪽이 원문과 안내로 보여 준다. 서버가 LaTeX를 해석할 일은 없다.

### 3. 서버가 뽑는 값

- **검색용 평문(`body_text`)**: 수식의 원문이 들어간다. `inlineMath`는 그 줄 안에 그 자리에 원문 그대로(앞뒤에 아무것도 붙이지 않는다), `blockMath`는 원문이 한 줄을 이룬다. 다이어그램은 `codeBlock`이므로 지금 규칙대로 원문이 들어간다(코드 블록의 글자가 한 줄, 안의 줄 바꿈은 그대로).
  - 웹앱의 `plainText`로 위 예를 뽑으면: `에너지는 E = mc^2 입니다.` / `\int_0^1 x^2 \, dx = \frac{1}{3}` / `flowchart LR⏎  A --> B` (줄마다 `\n`으로 잇는다. 빈 줄은 뺀다).
- **할 일 수**: 바뀐 것 없다(`taskItem`만 센다).
- **빈 본문 판정**: 바뀐 것 없다. 수식 하나만 있는 본문은 빈 본문이 아니다.
- **`file_refs`**: 바뀐 것 없다(수식과 다이어그램은 파일을 가리키지 않는다).

### 4. 공유 테스트 벡터(`contracts/body-vectors.json`)에 더할 경우

받는 예:

1. 문단 안의 `inlineMath`(글자 사이, 문단의 처음, 문단의 끝, 문단에 그것 하나뿐).
2. `heading` 안의 `inlineMath`.
3. `doc` 바로 아래의 `blockMath`. `blockquote` 안, `listItem`의 둘째 자식, `taskItem`의 둘째 자식.
4. `latex` 1자. `latex` 4,000자(ASCII).
5. `latex`가 공백뿐인 문자열(`" "`), 줄 바꿈이 든 문자열, `<script>`처럼 마크업으로 보이는 문자열, `\href{javascript:…}{x}`: **모두 받는다**(내용은 보지 않는다).
6. BMP 밖의 글자: `"😀"`를 2,000번 이은 `latex`(UTF-16으로 4,000) → 받는다.
7. 언어가 `mermaid`인 `codeBlock`(평범한 코드 블록과 같게 받는다). 내용이 `%%{init: …}%%`이든 `click A href "javascript:…"`이든 받는다.

거절하는 예:

8. `latex`가 없는 `inlineMath`·`blockMath`(`attrs` 없음, `attrs: {}`).
9. `latex`가 빈 문자열. `latex` 4,001자. `latex`가 문자열이 아님(숫자, `null`, 배열, 객체, 불리언).
10. BMP 밖의 글자: `"😀"` 2,000번 + `"x"`(UTF-16으로 4,001) → 거절. (스칼라 값으로 세면 2,001이라 받게 된다. 이 벡터가 2절의 물음을 고정한다.)
11. 모르는 속성: `{"latex":"x","display":true}`, `{"latex":"x","html":"<span>x</span>"}`.
12. 자리: `doc` 바로 아래의 `inlineMath`. `paragraph` 안의 `blockMath`. `codeBlock` 안의 `inlineMath`. `listItem`의 첫 자식인 `blockMath`.
13. `content`가 있는 수식. `marks`가 있는 수식. `text` 멤버가 있는 수식.

평문 벡터(서버가 `body_text`를 벡터로 고정한다면): 3절의 예 하나, `blockquote` 안의 `blockMath`, 수식만 있는 문단.

### 5. 서버가 하지 않아도 되는 것, 그리고 알아 둘 것

- **수식과 다이어그램은 보는 사람의 브라우저에서 그린다.** 서버는 원문을 저장하고 돌려줄 뿐이다. 그리는 쪽의 방어(KaTeX의 신뢰하지 않는 입력 설정, Mermaid의 엄격 설정과 그 뒤의 SVG 걸러 내기)는 `docs/spike-editor.md` 10절에 있다. 서버가 원문을 걸러 낼 필요는 없고, 걸러서도 안 된다(공격 문자열도 글자로는 정당한 본문이다).
- **콘텐츠 보안 정책을 둔다면**(지금 앱 페이지에는 없다):
  - `img-src 'self' data: blob:`와 `connect-src 'self'`를 권한다. 다이어그램 라이브러리는 그리는 동안 주소의 그림을 불러올 수 있는 문법이 있고(노드를 그림으로 그리기) 웹앱은 그 문법을 원문 단계에서 막지만, 정책이 한 겹 더 막아 준다.
  - `style-src`에 `'unsafe-inline'`이 없으면: 편집기와 수식은 동작한다(스크립트가 넣는 스타일시트를 쓰지 않고, 인라인 스타일은 CSSOM으로만 준다). **다이어그램은 색을 잃는다**: 그린 SVG 안의 `<style>` 요소가 막힌다. 그때는 웹앱이 그 스타일을 구성 가능한 스타일시트(`adoptedStyleSheets`)로 옮겨야 한다(`safe-svg.ts`의 한 곳). 정책을 정할 때 알려 달라.
  - `font-src 'self'`면 충분하다(KaTeX 글꼴은 앱의 `static/` 아래에서 온다).
- **정적 파일**: 빌드 산출물에 `KaTeX_*.woff2` 20개가 더해진다(해시가 든 이름, 이미 압축된 형식이라 `.br`·`.gz`를 만들지 않는다). 서버의 규칙(`has_content_hash`, `font/woff2`)은 그대로 맞는다.
- **고지**: 웹 고지(`static/THIRD_PARTY_NOTICES.txt`)에 KaTeX(MIT), KaTeX 글꼴(OFL-1.1), Mermaid와 그 의존성, CLDR 자료(Unicode-3.0)가 더해진다. 루트 `deny.toml`의 허용 목록은 손대지 않았다. `OFL-1.1`은 여전히 그 목록에 없고(글꼴에 한해 웹 도구가 받는다), ELK 레이아웃 엔진(`elkjs`, EPL-2.0 또는 GPL-3.0)은 번들에서 뺐다.

## 5. 그 밖에 넘길 것

- **`index.html`의 인라인 스크립트와 콘텐츠 보안 정책.** `index.html` 머리에 인라인 스크립트가 하나 있다(스타일시트가 그려지기 전에 기억해 둔 밝기와 밀도를 루트 요소에 넣는다. 어두운 화면을 쓰는 사람이 밝은 화면을 잠깐 보지 않게 하려는 것). 정책이 인라인 스크립트를 막는다면(막아야 한다) 이 하나는 **해시로** 허용해야 한다. 빌드가 `dist/csp.json`에 `{"script-src": ["'sha256-…'"]}`를 쓴다(`tools/build/inline-scripts.ts`). 서버는 시작할 때 그 파일을 읽어 `index.html`과 함께 보내는 정책의 `script-src`에 더하면 된다. `{{.BaseURL}}` 치환은 그 스크립트의 글자를 건드리지 않는다(스크립트 안에 그 자리 표시가 없다). 파일은 `static/` 밖이고 서빙 대상이 아니다.
- **base path를 스크립트가 읽는 자리.** `<meta name="fvoci:base" content="{{.BaseURL}}">`. 서버가 `index.html`의 자리 표시를 전부 치환하므로 따로 할 일은 없다. 라우터가 여기서 읽는다(인라인 스크립트로 전역 변수를 심지 않는다).
- **화면의 주소.** `/board/<보드>/<뷰>/<카드>`(오른쪽부터 생략 가능)와 `/`. 2.3의 "그 밖의 GET은 `index.html`"에 들어간다. 로그인·가입·오류 화면의 주소는 아직 없다.
- **전 묶음에서 넘긴 것**(변함없다): 온보딩 보드를 `onboarding` 표식으로 찾을 것, 템플릿 산출물의 식별자는 넣을 때 새로 만들 것(`PORTING.md`의 "내장 템플릿의 변환 산출물").

### 칸반과 갤러리

작성: 2026-11-10 23:40 KST. 화면은 `lib/state`의 저장소만 썼고 서버의 API 모양을 새로 지어낸 것은 없다.

#### 묻는 것

1. **갤러리의 미리보기에 쓸 것을 카드 목록이 실어 줄 수 있는가.** 원본의 갤러리는 카드마다 본문의 앞부분이나 첫 이미지를 보여 준다. 지금의 카드 목록(`Backend.cards`)에는 본문이 없고 `hasBody`, `tasksTotal`, `tasksDone`만 있다. 갤러리가 카드마다 `Backend.card`를 따로 부르지 않게 했으므로 미리보기와 대표 이미지는 그리지 않는다. 필요하면 목록의 카드에 "첫 이미지의 파일 id"와 "본문 앞부분의 글자(예: 200자)" 같은 요약을 실어 주는 길이 있어야 한다. 화면 쪽에서 그릴 자리는 `src/lib/components/card-face/CardFace.svelte`다.

#### 가정한 것

1. **선택지의 id는 클라이언트가 만든다.** "+ 그룹 추가"는 `createId('block')`으로 만든 id의 선택지를 보드의 속성 정의에 더한다(`Backend.patchBoard`). 원본과 같고, 선택 속성의 편집기(`onCreateOption`)가 이미 같은 가정을 한다. 서버가 선택지의 id를 정한다면 `src/lib/features/views/kanban/board-data.ts`의 `addGroup`이 답에서 id를 읽게 바꿔야 한다(그 id를 뷰의 `visibleOptionIds`에 넣는다).
2. **선택지를 지워도 서버는 카드의 값을 건드리지 않는다.** 지운 선택지의 id를 값으로 가진 카드는 화면에서 값 없는 열에 보이고, 실행 취소(선택지를 정의에 되돌려 넣기)로 제 열에 돌아온다. 서버가 선택지를 지울 때 카드의 값을 함께 지운다면 실행 취소로 돌아오지 않으므로, 지우기 전에 묻는 글(`kanban_delete_group_description`)을 고쳐야 한다.
3. **뷰의 `visibleOptionIds`, `hiddenOptionIds`는 통째로 쓴다.** 열을 숨기고, 보이고, 순서를 바꾸는 일은 `BoardStore.setViewFields`로 두 목록을 새 값으로 바꾼다. 값 없는 열은 빈 문자열 id(`''`)로 목록에 든다(원본과 같다).
4. **그룹 속성이 없는 보드 뷰.** 뷰의 `groupById`가 비어 있으면 묶을 수 있는 첫 속성으로 묶어 그리고(원본의 동작), 카드를 놓으면 그 속성의 값을 바꾼다. 뷰의 `groupById`를 채워 쓰지는 않는다. 서버나 변환기가 보드 뷰에 `groupById`를 늘 채워 준다면 `BoardStore.groupingOf`의 대체 규칙은 쓰이지 않게 된다.

#### 저장소(`lib/state`)에 남기는 것

- `BoardStore.dropCards`는 뷰의 순서를 쓰고 답을 기다린 뒤 카드의 속성을 쓴다. 그 사이에 화면은 카드가 떠난 열에 도로 선 것을 보게 되므로, 칸반이 놓은 모습을 그 호출이 끝날 때까지 스스로 그린다(`Kanban.svelte`의 `settling`). 두 변경을 먼저 한꺼번에 보여 주고 나서 보내도록 저장소를 고치면 그 우회는 지워도 된다.
- 놓은 직후(쓰기가 끝나기 전)의 실행 취소는 이미 끝난 쓰기까지만 되돌린다. 종단 테스트는 쓰기가 끝난 뒤에 실행 취소한다(`data-settling`이 사라질 때까지 기다린다).

#### 물을 것

1. **보드와 여러 블록을 한 번에 고치는 쓰기가 있는가.** 원본은 속성의 종류를 바꾸거나 지울 때 보드의 정의, 뷰들, 값이 있는 카드 전부를 요청 하나로 보냈다. 지금의 경계에는 없어서 종류 바꾸기는 `보드 1 + 고칠 뷰 수 + 값을 고칠 카드 수`번의 쓰기다(뷰와 카드는 나란히 보낸다). 카드가 수백 장인 보드에서는 느리고 중간 실패가 생긴다. 서버가 (가) 묶음 쓰기를 주거나 (나) 속성의 종류가 바뀔 때 값의 변환을 스스로 하거나 (다) 지금대로 두는 것 가운데 무엇인가.
2. **속성을 지우면 서버가 카드의 값과 뷰의 흔적을 정리하는가.** 정리한다면 화면이 뷰를 고치는 쓰기를 따로 보낼 필요가 없고, 실행 취소(속성을 되살리기)로 값이 돌아오는지도 서버에 달린다.
3. **종류와 맞지 않는 값을 서버가 검사하는가.** 예: 날짜 속성에 글자가 든 카드. 화면은 종류를 바꿀 때 새 종류가 읽지 못하는 값을 지우지만, 다른 클라이언트가 남긴 값이 있을 수 있다. 검사한다면 언제(보드 패치 때, 카드 패치 때) 무엇으로 거절하는가.
4. **보드의 속성 정의의 순서.** 보드 패치는 고친 정의와 지운 식별자만 담고 순서를 담지 않는다. 지운 속성을 되살리면 맨 끝에 온다. 순서를 바꾸는 쓰기(또는 정의 목록 전체를 보내는 쓰기)가 있는가.
5. **남의 댓글을 지울 수 있는 사람.** 원본은 보드 관리자가 남의 댓글을 지울 수 있었다. 화면은 자기 댓글에만 삭제 단추를 보인다. 서버의 규칙이 정해지면 맞춘다.
6. **댓글만 달 수 있는 사람(commenter)과 첨부.** 화면은 첨부 올리기와 삭제를 편집 권한(`canEdit`)에 묶었다. 댓글 권한으로 파일을 올릴 수 있는가.
7. **떠나는 순간의 쓰기.** 탭을 닫거나 숨길 때 저장하지 않은 본문을 보낸다(`pagehide`, `visibilitychange`). 서버를 부르는 구현이 그 요청을 페이지가 사라진 뒤에도 끝까지 보내는지(`keepalive`)는 그 구현의 몫이다. 본문의 한도(1 MiB)가 `keepalive`의 한도(64 KiB)보다 크다는 점을 알려 둔다.
