# 한국어 문구 검수

원본의 한국어 번역에서 고친 문구와 새로 채운 문구를 모두 모은 문서다. 검수하는 사람이 "이전"과 "이후"를 나란히 보고 고칠 곳을 고를 수 있게 하려는 것이다. 변환의 기록은 `docs/i18n-conversion.md`에 있다.

- 건수, 원 표의 행, 이전·이후의 표는 변환 도구의 보고에서 만들었다(2026-11-10 20:23 KST 실행). 도구는 2026-11-11에 지웠으므로 이 표들은 검수 전의 기록이고 다시 쓰이지 않는다. "이후"는 그때의 문구이고, 지금의 문구는 `messages/ko.json`에 있다. "고른 용어와 이유"의 예와 "보았지만 고치지 않은 것"의 문구는 손으로 적었다.
- "이전"은 원본 `ko.json`의 문구다. 옛 회사 이름이 든 문구 하나(`OnboardingTour.AddComments.Body`)만은 그 이름을 `fvoci`로 바꾼 뒤의 문구를 적었다.
- "영어"는 지금 화면에 나오는 영어다. 영어를 고친 메시지 6개(제품 이름 4개, 다시 쓴 것 2개)는 고친 뒤의 영어가 적혀 있다. 고치기 전의 영어는 `docs/i18n-conversion.md`의 "덮어쓴 문구" 표에 있다.
- 문구의 `<b>`는 굵은 글씨, `{이름}`은 실행할 때 들어가는 값이다.

## 고치는 법

- 고치는 곳은 `messages/ko.json` 하나다. 표의 id로 찾아 그 값을 고친다. 원본의 문구로 되돌리려면 표의 "이전"을 옮겨 적는다(굵은 글씨 `<b>…</b>`는 그 파일에서 `{#b}…{/b}`로 적는다).
- 고친 뒤에는 `pnpm --filter web run check`가 키 집합을, `test`가 영어 메시지에 없는 인자·태그와 닫히지 않은 괄호·태그를 본다. 이 문서의 표는 고치지 않는다.

## 건수

- 원 표("이상해 보이는 기존 문자열")는 44행이고, 그 행들에 적힌 id는 58개다.
- 행으로 세면: 고친 행 42개(그 가운데 2개는 행의 id 일부만 고쳤다), 메시지가 제거되어 해당 없는 행 2개. 42 + 2 = 44.
- 고친 행 가운데 1개는 제품 이름(결정 1) 때문에 고친 행이다. 그 행을 따로 세면 나머지는 43행이고, 그 가운데 고친 행이 41개, 해당 없는 행이 2개다.
- id로 세면: 고친 것 53개, 그대로 둔 것 2개, 메시지가 제거된 것 3개. 53 + 2 + 3 = 58.
- 원 표 밖에서 더 고친 id는 77개다: 제품 이름(결정 1) 3개, 영어를 다시 쓴 메시지(결정 5) 2개, 용어·꼴·어조의 통일과 조사 때문에 72개.
- 덮어쓴 한국어 메시지는 모두 130개다(53 + 77).
- 새로 채운 것은 18개이고, 그 가운데 2개는 처음 채운 값을 통일 때문에 고쳤다.
- 아래 표는 148행이다(130 + 18).

"이상한 문자열 43건"과 맞춰 볼 때 알아둘 것:

- 원 표는 43행이 아니라 44행이다. 43이 어떻게 센 수인지는 알지 못한다. 내가 찾은 맞춤은 위의 셋째 줄이다(제품 이름 때문에 든 `BoardPage.newVersion` 행을 결정 1의 몫으로 따로 센다). 그렇게 세면 43행 가운데 41행을 고쳤고 2행은 메시지가 제거되어 해당이 없다.
- 한 행에 id가 여럿인 행이 10개 있어 id로 세면 수가 더 크다.
- 한 행의 id 가운데 하나만 고친 행이 둘이다. 그대로 둔 id는 `Sidebar.export-archive`("아카이브 내보내기")와 `PropertyType.Select`("선택")다. 둘 다 원 표가 "다른 쪽과 다르다"는 것을 보이려고 함께 적은 것이고, 통일은 다른 쪽(`Sidebar.import-archive`, `PropertyType.MultiSelect`)을 고쳐서 했다.
- "채운 것 18건"은 그대로 18건이다.

꼴과 어조는 이렇게 맞췄다.

- **단추·메뉴·제목은 명사구다.** "한자어 + 하기"는 "하기"를 뗐다(삭제하기 → 삭제, 링크 복사하기 → 링크 복사, 보드 삭제 확인하기 → 보드 삭제 확인). 같은 영어 "Delete"가 "삭제"(10곳)와 "삭제하기"(5곳)로, "Add icon"이 "아이콘 추가"와 "아이콘 추가하기"로 갈려 있었다. 고유어 동사는 명사형 "-기"가 곧 명사구이므로 그대로 뒀다(숨기기, 내보내기, 가져오기, 만들기, 열기, 보내기, 지우기, 돌아가기, 둘러보기). 기본형으로 끝나던 제목 "웹에 게시하다"도 "웹에 게시"로 했다.
- **필터 조건은 명사형(-ㅁ)으로 끝낸다.** "~를 포함하지 않음", "~로 시작함"이 다수다. "~를 포함한다", "~로 끝나다", "~이다"를 "~를 포함함", "~로 끝남", "~임"으로 했다.
- **문장은 합니다체다.** 서술은 "~습니다", 물음은 "~하시겠습니까?"·"~습니까?", 요청은 "~하세요"·"~해 주세요"다. 원본의 요청문은 "~하세요"·"~주세요"(9곳)와 "~하십시오"(7곳)가 섞여 있었고 많은 쪽으로 맞췄다. 혼자 해요체이던 "죄송해요, 뭔가 잘못되었어요", "전에 본적 있나요?", "삭제할까요?"를 합니다체로 했다.
- **값 뒤에 받침에 따라 달라지는 조사를 두지 않는다.** 사용자 이름 뒤에는 "님"을 붙여 조사가 늘 같게 했다("{username} 님을", "{username} 님은"). 속성 이름 뒤에는 "속성"을 두었다("{propertyName} 속성을"). "{property}로 그룹화"는 "그룹화 기준: {property}"로, "유형을 A에서 B로"는 "유형: A → B"로 구조를 바꿨다. "을(를)" 같은 병기는 없앴다.
- **제품 이름 `fvoci` 뒤에도 같은 원칙이다.** 읽는 법이 정해지지 않았으므로 받침과 상관없는 조사만 썼다("fvoci의", "fvoci에", "fvoci에서").
- **문장부호.** 영어에 없는 느낌표("카드 삭제 확인!")를 뺐고, 빠진 따옴표와 괄호를 넣었고, 굵은 글씨 안에 들어가 있던 마침표를 밖으로 뺐다.

## 표

"묶음"은 그 문구를 고친 까닭이 어디서 왔는지다.

- **원 표 N행**: 원 표의 그 행이 든 문구다.
- **결정 1**: 영어 문구가 "Boards"를 제품 이름으로 쓰던 메시지다(원 표 44행의 `BoardPage.newVersion`은 "원 표 44행"으로 적혀 있다).
- **결정 5**: 영어 문구를 다시 쓴 메시지다.
- **통일**: 원 표에는 없지만 위의 용어·꼴·어조·조사의 원칙 때문에 함께 고친 문구다.
- **채움**: 원본 `ko.json`에 없어서 새로 옮긴 문구다. "이전"은 "(없음)"이고, 처음 채운 뒤에 통일 때문에 고친 것은 처음 채운 값을 함께 적었다.

"구분"의 "명사구"는 위의 "단추·메뉴·제목은 명사구다"와 "필터 조건은 명사형"에 해당하는 것이다.

## 확인하지 못한 것

- **화면에서 본 적이 없다.** 새 앱은 이 메시지들을 아직 쓰지 않는다. 길이, 줄바꿈, 단추 안에서의 모습은 보지 못했다. 원본 코드에서 그 문구가 어디에 쓰이는지만 읽었다.
- **내가 옮긴 것이고 다른 사람이 검토하지 않았다.** 이 문서가 그 검토를 위한 것이다.
- **조립되는 문구.** `CardDetailProperty.confirm-property-name-change-subtext`의 `{customText}`에는 `CardDetailProperty.property-name-change-subtext`가 들어간다(원본 `cardDetailProperties.tsx`). 고친 두 문구를 이으면 `"상태" 속성을 다음과 같이 바꾸시겠습니까? 유형: "선택" → "텍스트". …`가 된다. 새 앱이 같은 방식으로 조립한다는 전제다. 실행 취소 설명(`{description} 실행 취소`)에 들어가는 문구들도 마찬가지다.
- **"Boards 카테고리".** 서버 설계의 기본 카테고리 이름이 "Boards"라는 것은 서버 트랙의 코드에서 확인했다. 새 웹앱이 그 이름을 그대로 보여 줄지 번역해 보여 줄지는 정해진 것을 찾지 못했다.
- **`fvoci`의 읽는 법.** 조사를 피해 썼을 뿐 정하지 않았다.
