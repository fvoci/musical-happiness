# 스스로 정한 것

웹앱의 화면을 조립하는 동안 사용자가 자리에 없었다. 그동안 묻지 않고 정한 것을 여기에 모았다. 적은 때는 2026-11-10 22:58 KST부터 2026-11-11 01:25 KST까지이고, 2026-11-11 03:00 KST에 글과 순서를 다듬었다.

여기에 있는 것은 되돌리기 싼 것뿐이다: 화면 배치, 문구, 색, 동작의 세부, 수치. 항목마다 넷을 적는다.

- **무엇을** 정했는가. 항목의 첫 문단이다.
- **왜** 그 안인가.
- **다른 안**은 무엇이었는가.
- **바꾸려면** 어디를 고치는가.

## 읽는 법

- 경로는 `apps/web` 기준이다. 파일 이름만 적힌 것은 그 절이 다루는 폴더의 파일이다.
- **번호는 바뀌지 않는다.** 다른 문서와 코드의 주석이 그 번호로 부른다. 맨 앞 여섯 절의 1–58번은 "58번"처럼 부른다. 화면별 절은 번호를 따로 매겼고 "테이블의 14번"처럼 부른다.
- Q1–Q36은 `mobile-proposal.md`의 질문 번호다. 질문의 답과 "바꾸려면 어디를"은 그 문서의 "결정" 절에 모여 있다. 여기에는 화면마다의 자세한 사정이 있다.
- W1, W3, W5는 계획(`~/.claude/plans/fvoci-web-svelte.md`)의 단계 이름이다. W1은 순수 로직, W3은 보드 페이지, W5는 나머지 뷰와 기능이다.
- "지시"는 화면 조립을 맡긴 지시문을 가리킨다. "목업"은 `mobile-proposal.md`를 쓸 때 만든 화면 안이다.
- "생성 UI"는 shadcn-svelte가 만들어 준 부품(`src/lib/ui`)이다.
- 서버의 API 모양에 관한 가정은 이 문서가 아니라 `contract-assumptions.md`에 있다.

## 이 문서를 적은 뒤에 정해진 것

아래 넷은 이 문서의 항목을 바꾼다. 모두 사용자가 정했다. 코드에 넣은 것은 그 줄에 적었다.

| 무엇                  | 정해진 것                                                                                                                                                                         | 걸리는 항목                                          |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 카드를 지울 때 묻는가 | 어느 뷰에서나 묻지 않는다. 카드 상세도 같다(코드에 넣었다: 웹 연결의 tracer-bullet 8)                                                                                             | 카드 상세의 5번, "검토에서 나온 것과 처리"의 남긴 것 |
| 표시 설정의 이름      | 서버의 계약을 따른다. `brightness`는 `theme`, `vibration`은 `haptics`가 된다(코드에 넣었다: 웹 연결의 tracer-bullet 9)                                                            | 25번, 28번                                           |
| 기기에 둔 옛 이름     | 새 이름으로 옮기지 않는다(2026-11-11 11:05 KST). 옛 기기(`fvoci:display`, `fvoci:memory-settings`의 `brightness`, `vibration`)는 계정 설정이 오기 전 첫 그리기 한 번만 기본값이다 | 31번                                                 |
| 스크린샷을 두는 곳    | 다음부터 커밋하지 않는 폴더에 찍는다(코드에 넣었다: 웹 연결의 tracer-bullet 10, `target/screens/`)                                                                                | 작업 공간의 틀의 "그림", 뷰 머리글의 31번            |

- 카드 삭제는 사용자가 2026-11-11 02:12 KST에 정했다. 되돌리기는 실행 취소와 휴지통(30일)이 맡는다.
- 표시 설정의 값과 타입은 그대로다. 이름만 바뀐다.
- 저장소에 이미 든 그림 307장은 그대로 둔다.

## 구조

- **1.** `src/lib`의 층을 높이로 쌓고 린트로 검사한다(`fvoci/layer-order`). 표에 없는 폴더는 실패한다.
  - 왜: 기능끼리 못 가져온다는 규칙만으로는 아래 층끼리의 방향(예: 로직이 상태를 가져옴)을 막지 못한다.
  - 다른 안: 규칙 없이 관례로.
  - 바꾸려면: `tools/lint/layers.ts`의 `LAYERS`, `src/lib/README.md`의 표.
- **2.** 공용 부품(`lib/components`)은 `lib/state`를 가져오지 못한다.
  - 왜: 값과 콜백만 받아야 Storybook과 테스트에서 저장소 없이 그린다. 속성 편집기 15종이 이미 그렇게 돼 있다.
  - 다른 안: 공용 부품이 저장소를 직접 읽게.
  - 바꾸려면: 같은 파일의 `NEVER`.
- **3.** 화면이 서버를 못 부르게 하는 검사는 린트(`fvoci/no-direct-server`): `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `sendBeacon`, 그리고 경계의 구현(`state/memory`, 장차 `api`)의 import.
  - 왜: 완료 조건 "린트나 테스트로 확인".
  - 다른 안: 소스를 읽는 테스트.
  - 바꾸려면: `tools/lint/layers.ts`, 예외 파일은 `eslint.config.js`(`src/app/backend.ts` 하나).
- **4.** (2026-11-11에 거뒀다) 이 앱만의 메시지를 묶음 폴더(`messages-own/<묶음>/`)로 나누던 것. 지금은 모든 메시지가 `messages/<태그>.json` 한 파일에 있다.
- **5.** 라이선스 표기가 없는 번들 패키지는 예외 목록의 `stated`에 사람이 읽은 라이선스와 그 라이선스 파일에 있어야 하는 문장을 적어야 통과한다(지금 `svelte-toolbelt`, `khroma` 둘: MIT). 검사(`check.ts`)와 빌드의 고지 단계(`notices.ts`)가 같은 목록을 쓴다.
  - 왜: 빌드의 고지 단계가 표기 없는 패키지에서 뜻 모를 오류로 죽었다. 파일을 보고 추측해 통과시키면 검사가 아니다. 편집기 작업과 조립 작업이 같은 장치를 따로 만들어(`stated`, `unlabelled`) 하나로 합쳤다.
  - 다른 안: LICENSE 파일의 글로 자동 판별.
  - 바꾸려면: `tools/licenses/exceptions.json`의 `stated`, `packages.ts`의 `statedLicense`.

## 데이터의 경계 (`lib/state`)

- **6.** 저장소는 셋이다: 작업 공간(`Workspace`), 열린 보드(`BoardStore`), 열린 카드(`CardStore`). 화면은 이것만 쓰고 `Backend`를 직접 부르지 않는다.
  - 왜: 낙관적 갱신·되돌리기·실행 취소·정렬을 화면마다 다시 짜지 않게.
  - 다른 안: 화면이 `Backend`를 직접.
  - 바꾸려면: `src/lib/state/*.svelte.ts`.
- **7.** 고치기는 낙관적, **만들기와 지우기는 서버의 답을 기다린다.**
  - 왜: 식별자를 서버가 만든다. 임시 식별자를 진짜로 바꿔 끼우는 것은 그 사이의 다른 조작(끌기, 열기)과 얽힌다. 메모리 구현의 지연 40ms에서 눈에 띄지 않는다.
  - 다른 안: 만들기도 낙관적으로(임시 식별자).
  - 바꾸려면: `board.svelte.ts`의 `createCard`, `deleteCards`.
- **8.** 한 블록에 쓰기가 진행 중이면 서버에서 온 판을 붙들었다가 마지막 쓰기가 돌아온 뒤 가장 새 것을 적용한다.
  - 왜: 빠르게 두 번 고치면 첫 번째의 답이 두 번째 변경을 잠깐 지운다(깜박임).
  - 다른 안: 답을 그대로 적용.
  - 바꾸려면: `write.ts`의 `PendingWrites`.
- **9.** 거절된 변경은 "그 전의 모습"이 아니라 **반대 패치**를 지금 모습에 적용해 되돌린다.
  - 왜: 그사이 다른 사람이 같은 카드의 다른 것을 고쳤을 수 있다.
  - 다른 안: 스냅숏으로 되돌리기.
  - 바꾸려면: `board.svelte.ts`의 `#sendCardPatch`.
- **10.** 카드의 본문은 방에서 함께 고친다(`Backend.openDoc`, collab-r3): 웹은 본문을 HTTP로 쓰지 않고 409도 충돌 화면도 없다. 댓글의 409는 그대로다.
  - 왜: 둘이 한 본문을 치면 글자 단위로 합쳐진다. 묻거나 덮을 일이 없다.
  - 다른 안: HTTP로 통째 쓰고 409에 묻기(전의 방식).
  - 바꾸려면: `card.svelte.ts`의 `openBody`, `doc-room.ts`.
- **11.** 방의 문서를 가진 동안 `blockChanged`로 온 카드는 본문을 다시 읽지 않는다: 방의 것이 이긴다. 방이 없을 때는 남의 변경이 바로 보인다.
  - 왜: 서버의 투영은 방보다 늦다. 늦은 것이 화면을 덮으면 깜빡인다.
  - 바꾸려면: `card.svelte.ts`의 `cardChanged`.
- **12.** 실행 취소는 작업 공간에 하나다(보드를 바꿔도 이어진다). 한 번의 동작(여러 장 끌기)은 한 묶음.
  - 다른 안: 보드마다 따로.
  - 바꾸려면: `workspace.svelte.ts`의 `undo`, `board.svelte.ts`의 `newUndoGroup`.
- **13.** 목록의 순서: 카테고리는 사용자가 정한 순서·이름·id, 보드는 카테고리 안의 사용자 순서(어디에도 없는 보드는 기본 카테고리 끝에 제목순), **뷰는 제목순**(숫자를 수로 읽는 그 언어의 순서, 제목 없는 것은 끝), 댓글과 첨부는 오래된 것부터, 구성원은 보이는 이름순. 같으면 id.
  - 왜: 서버의 순서에 기대지 않기로 했다.
  - 다른 안: 뷰를 만든 순서로.
  - 바꾸려면: `src/lib/state/order.ts`.
- **14.** 메모리 구현은 목록을 일부러 뒤섞어 준다.
  - 왜: 순서에 기대는 화면을 지금 잡으려고.
  - 다른 안: 넣은 순서대로.
  - 바꾸려면: `memory/backend.ts`의 `scramble`.
- **15.** 씨앗: 템플릿 13개를 보드로, 사람 여섯(한국어·영어·중국어·일본어 이름), 보드마다 서너 명, 사람 속성에는 그 사람들, 첫 카드에 댓글 둘·둘째 카드에 하나, 첨부 하나, 카테고리 넷. **"Company Goals & OKRs"는 읽는 사람이 보기만 하는 보드.**
  - 왜: 템플릿에는 사람·댓글·첨부·사이드바가 없어 그 화면들이 비어 보인다. 읽기 전용 화면을 볼 보드가 필요하다.
  - 다른 안: 템플릿만.
  - 바꾸려면: `memory/seed.ts`의 `PEOPLE`, `SIDEBAR`, `VIEW_ONLY_KEY`, `COMMENTS`.
- **16.** 메모리 구현은 답마다 40ms 기다린다.
  - 왜: 낙관적 갱신이 답보다 먼저 보이는 것을 눈으로 볼 수 있게. 0이면 구분되지 않는다.
  - 다른 안: 0.
  - 바꾸려면: `src/app/backend.ts`의 `latency`.
- **17.** 메모리 구현은 읽는 사람의 설정을 기기에 두었다가(`fvoci:memory-settings`) 다음 방문의 새 세계에 돌려준다.
  - 왜: 새로 고칠 때마다 씨앗으로 돌아가면 고른 밝기와 시간대가 사라진다. 서버가 있으면 남을 값이다.
  - 다른 안: 매번 기본값.
  - 바꾸려면: `src/app/backend.ts`의 `keepSettings`.
- **18.** 메모리로 도는 동안 `window.fvociDev`에 손잡이를 둔다(같은 데이터를 다른 사람으로 보기, 다음 호출을 실패시키기).
  - 왜: 종단 테스트가 "다른 사람의 변경"과 실패를 만들어야 한다.
  - 다른 안: 주소의 인자로.
  - 바꾸려면: 같은 파일.
- **19.** 새 보드는 첫 뷰와 함께 만든다. 어떻게 만드는지는 45번에 있다.
  - 왜: 뷰 없는 보드는 보여 줄 것이 없다.
  - 다른 안: 뷰 없는 보드에 "뷰 추가" 화면.
  - 바꾸려면: `workspace.svelte.ts`의 `createBoard`.

## 주소와 언어

- **20.** 주소는 `/w/<워크스페이스>/boards/<보드>/<뷰>/<카드>`(오른쪽부터 생략, 사용자 결정 O3). `/`는 이 브라우저에서 그 사용자가 마지막으로 들어간 워크스페이스(아직 그의 것이면), 아니면 첫째로 가고 거기서 사이드바의 첫 보드로 간다(주소를 바꿔 쓴다). 맞지 않는 주소는 모두 같은 "찾을 수 없음"이다(`src/app/router.svelte.ts`, `App.svelte`).
  - 왜: 서버의 API가 워크스페이스에서 시작하고, 사용자는 여러 워크스페이스에 있을 수 있다. 마지막 워크스페이스는 사용자마다 `localStorage`에 둔다(`src/app/last-workspace.ts`).
  - 다른 안: 워크스페이스를 주소에 두지 않기(O2까지), 마지막에 본 보드로.
  - 바꾸려면: `src/app/router.svelte.ts`의 `parseRoute`·`routePath`, `App.svelte`의 첫 워크스페이스와 첫 보드 고르기.
- **21.** 카드를 열면 방문 기록에 한 칸이 생기고, 카드에서 다른 카드로 가면 그 칸을 바꿔 쓴다. 닫기는 이번 방문에서 연 카드면 "뒤로" 한 번, 주소로 바로 들어온 카드면 주소를 바꿔 쓴다.
  - 왜: "뒤로"가 닫기이고 "앞으로"가 다시 열기여야 한다(Q21). 바로 들어온 카드에서 "뒤로"는 앱을 떠나게 된다.
  - 다른 안: 늘 바꿔 쓰기.
  - 바꾸려면: 같은 파일의 `openCard`, `closeCard`.
- **22.** 서랍이나 시트가 열린 채 다른 주소로 가면(서랍에서 보드를 고르면) 새 주소가 그 겹의 기록 칸을 대신한다.
  - 왜: 그러지 않으면 "뒤로"가 한 번 헛돈다.
  - 다른 안: 겹을 먼저 닫고 그 뒤에 이동.
  - 바꾸려면: `router.svelte.ts`의 `go`, `lib/layout/back.svelte.ts`의 `releaseOverlayEntries`.
- **23.** base path는 `<meta name="fvoci:base">`에서 읽는다.
  - 왜: 인라인 스크립트로 전역 변수를 심으면 콘텐츠 보안 정책에 해시가 하나 더 든다.
  - 다른 안: 인라인 스크립트가 `window.baseURL`을 심기.
  - 바꾸려면: `index.html`, `router.svelte.ts`의 `readBasePath`.
- **24.** 언어는 계정 설정 `language`다(사용자 결정). `auto`는 브라우저의 언어 가운데 메시지가 있는 첫 번째, 없으면 영어. 기기의 사본(`fvoci:locale`)으로 로그인 전과 첫 그리기를 하고, 계정의 설정이 다르면 따라가며 새로 고친다.
  - 왜: 다른 기기에서도 같은 언어로 뜨게. 계정을 알기 전에도 언어가 필요해 사본을 둔다. 모든 글이 메시지라 새로 고치는 것이 가장 단순하다.
  - 다른 안: 새로 고치지 않고 다시 그리기. 다른 탭이 바꾼 언어는 그 탭을 새로 읽을 때 따라간다.
  - 바꾸려면: `src/app/locale.ts`.

## 표시 설정과 기기 설정

- **25.** 표시 설정 넷의 이름과 기본값: `theme: 'auto'`, `cardOpen: 'center'`, `density: 'auto'`, `haptics: true`(처음 이름은 `brightness`, `vibration`이었다). 순수 로직은 `lib/logic/display.ts`(지역 설정 `regional.ts`의 옆), 지금 값은 `lib/display.svelte.ts`.

- **열은 칸 너비에서 양쪽 28px를 뺀 만큼, 많아야 384px이고, 칸이 더 넓으면 가운데에 선다.** 양옆의 여백을 `max(1.75rem, (100% − 24rem) / 2)`로 주었다.
  - 바꾸려면: `Kanban.svelte`의 스크롤 상자 클래스, `KanbanColumn.svelte`의 `max-w-sm`.
- **마지막 열 뒤에 "+ 그룹 추가"와 숨긴 열이 한 장 더 있고, 탭 줄에도 그 탭이 있다("숨겨진 열 N", 숨긴 열이 없으면 "더 보기").**
  - 왜: 좁은 칸에서도 같은 부품이어야 창 크기가 바뀔 때 갈아 끼우지 않는다.
  - 다른 안: 좁은 칸에서는 뷰의 "…" 메뉴로 옮기기.
  - 바꾸려면: `HiddenColumns.svelte`, `Kanban.svelte`의 `tabs`.
- **탭 줄의 높이는 40px, 넉넉한 밀도에서 44px. 탭 이름은 12rem에서 줄인다.**
  - 바꾸려면: `ColumnTabs.svelte`.
- **열 안의 스크롤은 "같은 픽셀"이 아니라 "같은 내용"이 남는다.**
  - 왜: 열 너비가 바뀌면 제목이 다르게 접혀 카드 높이가 달라지고, 브라우저의 스크롤 앵커가 보던 카드를 제자리에 둔다. 테스트는 초점이 있던 카드가 여전히 보이는지를 본다.

#### 갤러리

- **카드의 최소 너비는 14rem(224px)다.** 휴대폰(412px 이하)에서 1열, 칸이 484px부터 2열, 720px부터 3열.
  - 다른 안: 10rem쯤으로 낮춰 휴대폰에서 2열(속성이 켜진 카드에는 좁다).
  - 바꾸려면: `Gallery.svelte`의 `grid-cols-[repeat(auto-fill,minmax(min(100%,14rem),1fr))]`.
- **한 줄의 카드는 높이가 같다.**
  - 바꾸려면: `Gallery.svelte`의 `h-full`.
- **본문 미리보기와 대표 이미지는 그리지 않는다.**
  - 왜: 카드 목록에 본문이 없다(`contract-assumptions.md`의 칸반 1, 사용자 결정을 기다린다).
- **끌어서 순서를 바꾸지 않는다.**
  - 왜: 격자는 두 축이고 `Sortable`은 한 축만 다룬다. 순서는 뷰 머리글의 정렬에 맡긴다. 그래서 메뉴에 "선택"과 "다른 열로 이동"도 없다.
- **"+ 새로 만들기"는 격자의 마지막 칸이다(고칠 수 있을 때)**.

#### `mobile-proposal.md`의 질문

- **Q3 (A)**: 칸이 544px 미만이면 한 열씩 멈추고(CSS scroll snap) 위에 탭 줄. 바꾸려면 `Kanban.svelte`의 스크롤 상자의 `snap-x snap-mandatory`와 `ColumnTabs.svelte`, 경계는 `app.css`의 `--container-columns`.
- **Q4 (가, 다)**: 끄는 동안에는 snap을 끄고(`dragging ? 'snap-none' : …`) 보드의 `data-drag-scroll="x"`가 가장자리에서 옆 열로 넘긴다. 브라우저 테스트로 확인했다(`e2e/kanban.spec.ts`의 "at the edge of the screen…": 끄는 동안 `scroll-snap-type`이 `none`이고, 놓은 뒤 `x mandatory`로 돌아오며 카드가 다음 열에 놓인다). 카드 메뉴의 "다른 열로 이동"은 `CardMenu.svelte`. (나) 탭 위에 올리면 넘어가기는 만들지 않았다.
- **Q16**: 열의 "+"는 그 열에 만든다. 뷰 머리글의 "새로 만들기"가 "지금 보이는 열에" 만들게 하려면 칸반이 보던 열을 머리글에 알려 줄 길이 필요한데 `ViewProps`에 그 길이 없다. 만들지 않았다(질문으로 남긴다).
- **Q22 (가)**: 카드의 "…"는 `can-hover:`에서만 숨고, 카드나 단추에 초점이 있으면 보인다. `CardMenu.svelte`의 단추 클래스.
- **Q24**: 카드의 터치 드래그(300ms 길게 누르기)와, 지시에 따라 열의 터치 드래그도 된다. 메뉴 항목("왼쪽으로"·"오른쪽으로", "다른 열로 이동")도 함께 있다.
- **Q28**: 갤러리는 열 수만 칸을 따른다.
- **Q31 (가)**: 칸 544px 이상은 256px 열의 자유 스크롤, 992px 이상은 272px. `KanbanColumn.svelte`의 `@columns/pane:w-64 @header/pane:w-68`.
- **Q33 (3)**: 위 "보던 열의 뜻". 열·카드·메뉴는 단계가 바뀌어도 같은 부품이다(클래스만 바뀐다). 진행 중인 드래그는 `Sortable`이 취소한다(테스트 "a window that changes width under a drag cancels it").

#### 테스트가 보드의 너비를 정하는 방식

종단 테스트는 창의 너비를 바꿔 **보드의 너비**를 정해진 값(휴대폰 412, 펼친 기기 570, 데스크톱 1024)으로 맞춘 뒤 시작한다(`e2e/kanban.support.ts`의 `fitPane`, `PANE`). 틀이 바뀌어도 같은 보드를 본다.

이 방식은 틀이 자리 표시이던 때에 정했다. 그 틀은 사이드바(256px)가 늘 떠 있어서 `mobile` 프로젝트의 칸이 156px였고, 너비를 맞추면 창이 668px가 되어 메뉴가 시트가 아니라 드롭다운으로 떴다. 메뉴의 줄은 `data-action`으로 찾으므로 시트든 드롭다운이든 통과한다. 지금의 틀에서 창이 얼마가 되는지는 다시 확인하지 않았다.

#### 모바일 안의 질문

#### 그 밖에 정한 것

1. **hover가 없는 기기에서는 행에 "…" 하나만 보이고 "열기"는 그 메뉴의 첫 항목이다.**
   - 왜: 좁은 화면의 제목 열은 160–206px이고 44px 단추 둘을 늘 그리면 제목이 서너 글자만 남는다.
   - 다른 안: 둘 다 늘 보이게(Q22의 글자 그대로), 또는 "열기"만 보이게(삭제·복제에 닿을 길이 없어진다).
   - 바꾸려면: `Row.svelte`의 열기 링크 클래스 `hidden can-hover:flex`를 `flex`로 바꾸면 늘 보인다. 메뉴의 "열기" 줄은 `menus.ts`의 `rowMenu`.
2. **행의 손잡이는 제목 칸 전체다.** 마우스는 누른 채 4px, 손가락은 300ms, 키보드는 제목 칸에서 Space. 점 여섯 개는 hover 기기에서 행을 가리킬 때만 보이는 표시일 뿐이다. 누르고 움직이지 않으면 클릭이고 제목을 고친다.
   - 왜: 따로 44px 손잡이를 둘 자리가 좁은 제목 열에 없고, Tab이 멈추는 곳이 행마다 늘지 않는다.
   - 다른 안: 따로 둔 손잡이 단추.
   - 바꾸려면: `Row.svelte`의 `data-drag-handle`.
3. **끄는 동안 빈자리를 열지 않고 선을 긋는다**(행은 가로선, 열은 세로선). 끌리는 것은 제자리에 흐리게 남고 작은 딱지가 포인터를 따라간다. 키보드로 나르는 동안에는 행(열은 머리글만)이 놓일 자리로 옮겨 선다.
   - 왜: 표에서 행 하나만큼 빈자리가 열리면 그 아래 수백 행이 밀린다.
   - 다른 안: 칸반처럼 빈자리.
   - 바꾸려면: `table-controller.svelte.ts`의 `rowMarker`·`columnMarker`·`shownLists`·`headerColumns`, 선의 생김새는 `host.ts`의 `DROP_LINE_ROW`와 `HeaderCell.svelte`.
4. **한 번에 한 칸만 편집기다.** 모든 칸은 `PropertyValue`의 `display`로 그리고, 누른 칸만 `edit` + `startOpen`으로 바꾼다. 끝났는지는 그 칸의 DOM에서 읽는다: 글 칸은 초점이 칸을 떠나면, 선택기는 방아쇠의 `aria-expanded`가 참에서 거짓이 되면.
   - 왜: 속성 부품에 "끝났다"는 콜백이 없고, 공용 부품을 고치면 카드 상세 작업과 겹친다.
   - 다른 안: `PropertyValue`에 `onDone`을 더한다(더 깔끔하다. 합친 뒤의 후보).
   - 바꾸려면: `cell-editing.svelte.ts`.
5. **체크박스 칸은 편집 상태가 없다.** 표시로 그리고 칸이 누름을 받아 바로 바꾼다(키보드는 Space·Enter). 화면 낭독기에는 안의 체크박스가 "사용할 수 없음"으로 읽힌다(표시 모드가 `disabled`라서). 공용 부품에 "읽기 전용이지만 꺼지지 않은" 표시가 생기면 바꾼다.
   - 왜: 편집 모드의 체크박스는 칸마다 Tab이 멈추는 단추가 된다.
   - 바꾸려면: `Row.svelte`, `table-controller.svelte.ts`의 `host.activate`.
6. **칸에서 선택지를 만들거나 이름·색을 바꾸거나 지우지 않는다**(있는 선택지를 고르기만).
   - 왜: 속성 정의를 바꾸는 일은 카드 상세의 것이라는 지시의 연장으로 봤다.
   - 다른 안: 칸에서도 하게 하기.
   - 바꾸려면: `Row.svelte`의 편집 `PropertyValue`에 `onCreateOption` 등을 넘기면 된다.
7. **열의 수치**: 최소 100px, 최대 800px, 너비가 저장돼 있지 않은 열은 150px(100px이면 날짜가 잘린다), 손잡이의 화살표 한 번 16px, 메뉴 한 번 48px.
   - 바꾸려면: `columns.ts`의 `TABLE_SETTINGS` 한 곳.
8. **너비는 "지금 보이는 너비"에서 바꾼다.** 제목 열이 절반 제한에 걸려 저장된 값보다 좁게 보일 때 "더 좁게"는 보이는 너비에서 줄이고, "더 넓게"는 아무것도 하지 않는다(보이지 않는 값만 커지지 않게). 손잡이를 끌 때도 같다.
   - 바꾸려면: `column-resize.svelte.ts`.
9. **정렬 메뉴는 그 열 하나로 뷰의 정렬을 바꾼다**(다른 정렬은 사라진다). 정렬을 푸는 항목은 머리글 메뉴에 없다(뷰 머리글의 일).
   - 바꾸려면: `table-controller.svelte.ts`의 `headerActions`.
10. **그룹 접기**: 고칠 수 있는 사람은 뷰에 저장(`collapsedGroups`), 읽기만 하는 사람은 이번 방문 동안만(저장하지 않는다). 값 없는 그룹도 접을 수 있다(`collapsedGroups`에 `''`가 들어간다).
    - 다른 안: 읽기만 하는 사람은 못 접게.
    - 바꾸려면: `table-controller.svelte.ts`의 `toggleGroup`.
11. **그룹과 새 카드**: 그룹 머리의 "+"와 그룹 맨 아래의 "+ 새로 만들기"가 그 그룹의 값으로 만든다. 접힌 그룹의 "+"는 그룹을 펴고 만든다. 만든 사람·고친 사람으로 묶인 뷰(값을 정할 수 없다)에서는 그룹별 추가가 없고 표 맨 아래에 하나만 있다. 새 카드는 뷰의 필터가 요구하는 값도 받는다(조립 파일의 `addCard`와 같게).
    - 바꾸려면: `table-controller.svelte.ts`의 `addCard`·`canAddTo`·`canAddLoose`.
12. **행 메뉴**: 삭제는 묻지 않는다(실행 취소가 된다). 삭제 뒤 초점은 그 자리에 온 이웃 행의 제목 칸, 복제 뒤 초점은 새 행의 제목 칸. 링크 복사는 화면 낭독기에만 "복사되었습니다!"를 알린다(보이는 표시는 없다).
    - 바꾸려면: `table-controller.svelte.ts`의 `#deleteCard`·`#duplicateCard`·`#copyLink`.
13. **계산**: 저장된 값이 없으면 제목 열은 "개수", 나머지는 없음. 그 종류가 가질 수 없는 계산이 저장돼 있으면 없음으로 본다. 메뉴는 `propertyBehavior(type).calculationOptions`에 **체크박스의 넷(체크된 개수 등)과 날짜의 셋(가장 이른 날짜 등)을 테이블에서 보탰다**(`lib/logic/properties.ts`에는 없다). 메시지가 없던 네 계산(빈 값 개수 등)의 이름을 새로 지었다.
    - 바꾸려면: `calculation-names.ts`의 `TABLE_EXTRAS`와 `NAMES`, 문구는 `messages/`의 `table_*`.
14. **Ctrl/⌘+Z는 표가 받지 않고 틀이 받는다(50번).** 표의 칸에 초점을 둔 채 누른 단축키는 틀까지 올라가 한 번 처리된다. 입력 칸 안에서는 틀도 가로채지 않는다. 종단 테스트(`e2e/table.spec.ts`의 Ctrl+Z 세 곳)가 틀의 단축키로 통과한다.
    - 다른 안: 표가 받고 전파를 멈춘다(같은 일을 두 곳이 한다).
    - 바꾸려면: `features/shell/undo-keys.ts`, `AppShell.svelte`의 `onkeydown`.
15. **키보드**: 표는 Tab이 한 번 멈추는 곳이다(초점이 있던 칸). 화살표로 칸 사이, Home·End로 행의 끝, Ctrl+Home·End로 표의 끝, Enter·F2로 편집(머리글은 메뉴, 계산 칸은 메뉴, 그룹 머리는 접기, "+ 새로 만들기"는 만들기), Escape로 나오기, 체크박스는 Space. 칸 안의 단추("열기", "…", 너비 손잡이, 그룹의 접기·"+")는 그 칸이 멈추는 곳일 때만 Tab으로 닿는다. 글자를 치면 바로 편집이 시작되는 것은 없다. `tabindex`는 상태로 그리지 않고 초점을 따라 DOM에서 옮긴다(수백 행을 다시 그리지 않으려고).
    - 바꾸려면: `grid-focus.ts`, `Table.svelte`의 `onKeyDown`.
16. **읽기만 하는 보드**: 머리글 메뉴·너비 손잡이·열과 행의 끌기·"+ 새로 만들기"·계산 메뉴가 없고 칸을 눌러도 편집기가 되지 않는다. 행 메뉴에는 "열기"와 "링크 복사"만 남는다. 표에 `aria-readonly`.
    - 바꾸려면: 각 부품의 `canEdit`.
17. **큰 표**: 화면 밖의 행은 `content-visibility: auto`로 배치와 칠하기를 건너뛴다(한 번도 안 그려진 행은 36px, 넉넉한 밀도 44px로 친다). 행의 "…" 메뉴는 처음 누를 때 만든다. 행의 "…"와 점 아이콘은 공용 `IconButton`·아이콘 부품이 아니라 같은 모양의 평범한 요소다(행마다 부품 하나의 값이 든다. 이름은 `aria-label`로 같다). 가상 스크롤은 하지 않았다.
    - 바꾸려면: `host.ts`의 `ROW_SKIPPED`·`MORE_BUTTON`, `Row.svelte`.
18. **행 사이의 선은 행이 긋고, 고정된 제목 칸은 위아래 1px를 칠하지 않는다.**
    - 왜: 고정된 칸은 따로 그려지는 층이라 배율 3에서 1px 어긋나 이웃 행의 선을 덮었다(스크린샷에서 발견).
    - 바꾸려면: `Row.svelte`의 `border-y-transparent bg-clip-padding`.
19. **끌어 놓은 자리의 번역은 저장소가 한다.** 표는 보이는 행 가운데의 자리와 보이는 행의 목록을 `dropCards`에 넘기고(`CardDrop`의 `index`와 `shown`), 저장소가 "그 그룹의 모든 카드(필터·검색에 가려진 것 포함) 가운데의 자리"로 바꾼다: 위에 보이는 행의 바로 뒤. 칸반과 같은 규칙이다(50번).
    - 왜: 그대로 세면 필터가 걸린 뷰에서 엉뚱한 자리에 놓인다.
    - 바꾸려면: `lib/state/card-order.ts`의 `placeAmongAll`.
20. **열 머리글에 속성 종류의 아이콘이 없다**(이름만). 숫자 열을 오른쪽에 맞추지도 않았다.
    - 왜: 지시에 없다.
    - 바꾸려면: `HeaderCell.svelte`, `Row.svelte`.
21. **오른쪽에서 왼쪽으로 쓰는 화면**: 논리 속성(`start`, `border-e`)을 쓰고 손잡이와 화살표의 방향을 뒤집지만, 화면으로 확인하지 않았다.

#### 스스로 정한 것

##### 틀과 머리

1. **보드와 뷰의 이름을 세 틀 모두의 윗줄에 보인다.** 목업(`docs/mobile/card-a-1280.png`)이 그렇고, 틀마다 윗줄의 짜임이 같으면 창 크기가 바뀔 때 움직이는 것이 적다.
   - 다른 안: 좁은 단계에서만.
   - 바꾸려면: `CardHeader.svelte`의 `card-location` 문단을 `frame === 'full'`로 감싼다.
2. **가운데 대화상자의 높이는 내용과 상관없이 `min(100dvh − 키보드 − 4rem, 56rem)`이다.** 내용이 늦게 도착해도(본문, 댓글) 상자가 튀지 않고 댓글 입력 칸의 자리가 고정된다.
   - 다른 안: 내용만큼만(짧은 카드는 작은 상자).
   - 바꾸려면: `frame.ts`의 `dialog` 줄의 `h-[…]`. 옆 판의 너비 30rem(+오른쪽 안전 영역, 보드를 적어도 3.5rem 남긴다)과 대화상자의 최대 너비 48rem도 그 파일이다.
3. **가운데 대화상자의 바탕은 `popover`, 전체 화면과 옆 판은 `background`다.** 어두운 화면에서 떠 있는 상자가 뒤의 보드와 구별된다.
   - 다른 안: 셋 다 `background`.
   - 바꾸려면: `frame.ts`의 `bg-…`.
4. **실행 취소와 다시 실행을 카드의 "…" 메뉴에 두었다(지시에 없던 것).** 좁은 단계에서 카드는 화면 전체라 다른 곳의 단추가 가려지고, 손가락 화면에는 Ctrl+Z가 없다. 첨부·댓글 삭제를 묻지 않고 하려면 되돌릴 길이 카드 안에 있어야 했다. 단축키는 달지 않았다(셸이 달 것과 겹치면 두 번 되돌린다).
   - 다른 안: 셸의 단추에만 둔다.
   - 바꾸려면: `CardHeader.svelte`의 `actions`에서 `undo`, `redo` 두 줄.
5. **카드 삭제도, 첨부와 댓글의 삭제도 묻지 않는다.** (처음에는 카드 삭제만 물었다: 카드는 지우면 닫히므로 되돌릴 메뉴도 함께 사라진다. 첨부와 댓글은 카드가 열린 채이고 메뉴의 실행 취소로 돌아온다.) **그 뒤 사용자가 카드 삭제도 "묻지 않는다"로 정했다**(2026-11-11 02:12 KST. 맨 위의 "이 문서를 적은 뒤에 정해진 것"). 코드도 묻지 않는다(웹 연결의 tracer-bullet 8): 카드는 지우기 전에 쓰던 본문을 저장하고, 닫히고, 보드 화면의 "실행 취소"로 돌아온다.
   - 다른 안: 셋 다 묻는다.
   - 바꾸려면: 다시 묻게 하려면 `CardHeader.svelte`의 삭제 항목(`run: onDelete`)을 `ConfirmDialog`로 감싼다(3d8a963 전의 모양). 첨부와 댓글은 `CardAttachments.svelte`·`CardComments.svelte`의 삭제 단추.
6. **"복제"는 복사본을 같은 대화상자에 연다.** 조립 파일이 `onOpenCard`를 주지 않으면 복사본만 만들고 열지 않는다.
   - 바꾸려면: `CardContent.svelte`의 `duplicate`.
7. **"링크 복사"는 주소창의 주소를 복사하고, 클립보드를 쓸 수 없는 페이지(보안 연결이 아닌 LAN 주소)에서는 아무 말 없이 아무것도 하지 않는다.** 실패를 알리는 문구를 정하지 않았다.
   - 바꾸려면: `CardHeader.svelte`의 `copyLink`.
8. **닫을 때 본문에 쓴 것이 서버에 다 닿지 않았으면(연결이 없다, 방에 들지 못했다, 이미지가 올라가는 중) 한 번은 열어 둔다.** 한 번 더 닫으면 닫힌다. 뒤로 가기는 막지 못하므로 그때는 기다리는 것을 보내기만 한다.
   - 다른 안: 늘 바로 닫는다(쓰던 글이 조용히 사라질 수 있다).
   - 바꾸려면: `CardDialog.svelte`의 `close`.
9. **닫으면 초점은 보드의 `[data-card="<카드 id>"]`로 간다**(마지막으로 보이던 카드. 그것이 없거나 초점을 받을 수 없으면 대화상자를 열 때 초점이 있던 곳). 뷰들이 `data-card`의 값으로 카드 id를 준다는 것에 기댄다.
   - 바꾸려면: `CardDialog.svelte`의 `focusOnClose`.
10. **템플릿인 카드를 열면 "템플릿을 수정하는 중" 줄을 보인다.** 그 문구가 메시지에 이미 있어서 넣었다. 템플릿 카드의 그 밖의 다른 점(이름, 메뉴)은 만들지 않았다.

##### 제목과 아이콘

11. **제목에서 Enter는 줄을 바꾸지 않고 편집을 끝낸다. 붙여 넣은 줄 바꿈은 빈칸이 된다. Escape는 저장된 제목으로 되돌리고 카드는 닫지 않는다.** 제목은 여러 줄로 접히는 한 문단이다. 입력이 800ms 멈추면, 그리고 칸을 떠날 때 저장한다.
    - 바꾸려면: `CardTitle.svelte`(`PAUSE`, `onkeydown`).
12. **"새로 만든 빈 카드"는 제목이 비어 있고 본문이 없는 카드로 본다.** 그런 카드를 고칠 수 있는 사람이 열면 제목에 초점이 간다. 만든 시각이나 만든 사람은 보지 않는다.
    - 다른 안: 조립 쪽이 "방금 만들었다"를 인자로 알려 준다.
    - 바꾸려면: `CardContent.svelte`의 `blank`.
13. **"아이콘 추가"는 늘 보이는 흐린 단추다.** hover로 숨기지 않았다(키보드와 손가락 화면에서 같은 것이 보인다). 무작위 이모지의 목록 80개는 이 폴더의 것이다(`icons.ts`의 `CARD_EMOJI`). 이모지 선택기가 생기면 `CardTitle.svelte`의 두 곳(`randomEmoji()`를 부르는 곳)이 그것을 연다.

##### 속성

14. **속성 정의의 메뉴는 `PickerSurface` 한 장에 두 쪽이다**(이름 칸·종류·삭제 / 종류 목록). 공용 `ActionMenu`는 입력 칸과 하위 메뉴를 담지 못한다. 좁은 단계에서는 시트, 그 밖에서는 팝오버라는 규칙은 그대로 따른다.
    - 다른 안: "이름 바꾸기"를 누르면 이름이 그 자리에서 입력 칸이 되고, 종류는 두 번째 `ActionMenu`.
    - 바꾸려면: `PropertyMenu.svelte`.
15. **새 속성의 이름은 종류의 이름이고, 같은 이름이 있으면 번호를 붙인다**("Text", "Text 2").
    - 바꾸려면: `property-change.ts`의 `freePropertyName`.
16. **속성을 더하면 그 속성의 메뉴가 바로 열린다**(이름을 지으라는 뜻). 좁은 단계에서는 시트가 닫히고 곧 다른 시트가 열린다.
    - 바꾸려면: `CardProperties.svelte`의 `added`.
17. **테이블 뷰에서 연 카드에서 더한 속성은 그 테이블의 보이는 속성에 들어간다.** 다른 종류의 뷰에서는 보드에만 더한다.
    - 바꾸려면: `property-actions.ts`의 `addProperty`.
18. **종류를 바꿀 때 값의 규칙.** `property-change.ts` 머리의 표가 전부다. 눈여겨볼 것 둘: (가) 선택·다중 선택을 글 종류로 바꾸면 선택지의 이름이 글로 남는다. (나) 새 종류가 읽지 못하는 값은 카드에서 지운다. 확인 대화상자의 "유지되는 값 N개, 삭제되는 값 M개"가 실제로 일어나는 일과 같아야 해서다. 한 번의 실행 취소로 정의와 값이 모두 돌아온다.
    - 다른 안: 읽지 못하는 값을 숨긴 채 남긴다(쓰기가 줄고, 종류를 되돌리면 값이 다시 보인다).
    - 바꾸려면: `planTypeChange`의 `convert`.
19. **종류 바꾸기는 값이 있는 카드가 하나라도 있으면 묻는다**(사라지는 값이 없어도). 사라지는 값이 있을 때만 단추가 위험한 색이다.
    - 다른 안: 사라지는 값이 있을 때만 묻는다.
    - 바꾸려면: `PropertyMenu.svelte`의 `chooseType`.
20. **종류를 바꾸면 뷰에서 그 속성의 필터 절, 계산, 그룹의 열 목록을 뺀다. 새 종류가 그룹을 만들지 못하면 그룹 기준도, 날짜가 아니면 캘린더의 기준 날짜도 뺀다(지시에 없던 것).** 필터의 조건과 계산은 종류에 딸린 것이라 남겨 두면 뷰가 깨진다. 보이는 속성, 정렬, 열 너비는 둔다.
    - 바꾸려면: `property-change.ts`의 `viewWithoutProperty`.
21. **속성을 지울 때 카드에 든 값은 지우지 않는다.** 뷰들에서 그 속성의 흔적(보이는 속성, 정렬, 필터, 그룹, 캘린더 기준, 너비, 계산)만 정리한다. 남은 값은 어디에도 보이지 않고, 실행 취소는 쓰기 한 번으로 값까지 되살린다. 값까지 지우려면, 지금은 묶음 쓰기가 없어 카드 수만큼 쓰기가 필요하다. 서버는 값을 건드리지 않는다(`docs/contract-pending.md` 9절).
    - 바꾸려면: `property-actions.ts`의 `deleteProperty`.
22. **속성 이름의 칸은 7.5rem, 카드의 폭이 576px 이상이면 10rem이다.** 긴 이름은 말줄임표로 잘린다(메뉴를 열면 전체가 보인다). 목업은 6.5rem과 9rem이었고 "Last updated time" 같은 이름이 너무 일찍 잘려 넓혔다.
    - 바꾸려면: `CardProperties.svelte`의 `grid-cols-[…]`.

##### 본문

23. **본문은 친 대로 방에 간다**(30ms 모아 한 프레임). 저장 상태는 서버가 다 받을 때까지와 그 뒤 0.6초 "저장 중…", 그 뒤 "저장됨", 방에 다 가지 못한 채 연결이 없거나 방 밖이면 "저장되지 않음"이다(지시에 없던 것: 0.6초는 키마다 깜박이지 않게).

24. **방의 문서가 오기 전에는 카드의 본문을 표시기로 보이고, 문서가 오면 편집기로 바꾼다.** 그 사이 본문을 누른 자리(5초 안)에 커서를 둔다. 서버가 문서를 새로 만들면 편집기를 새로 만들고, 읽는 사람이 편집기에 있었으면 커서 자리와 초점을 옮긴다.
    - 바꾸려면: `CardBody.svelte`, `caret-keeper.ts`.
25. **읽기 전용이면 까닭을 본문 아래 한 줄로 알린다**: 읽기 권한, 연결 끊김(다시 붙으면 스스로 풀린다), 다시 받는 중, 방에 들지 못함(다시 해 보기 단추), 볼 수 없게 됨. 들어가는 중과 다시 받는 중은 1초가 넘을 때만 보인다. 보기·댓글 역할도 읽기 전용 편집기로 남의 변경을 따라 본다.
    - 바꾸려면: `body-notes.ts`의 `roomNote`.
26. **쓴 것이 서버에 닿지 못하고 버려지면(문서가 새로 만들어짐, 거절, 너무 큼) 본문 위에 닫을 때까지 남는 알림을 띄운다.**
    - 바꾸려면: `body-notes.ts`의 `lostNote`, `CardBody.svelte`의 `body-lost`.
27. **본문의 실행 취소(Ctrl+Z)는 Y의 실행 취소로 자기 변경만 되돌리고, 앱의 실행 취소 줄에는 서지 않는다**(전과 같이 본문 칸 안의 키는 칸의 것이다).

### 편집기: 수식, 다이어그램, 이모지 (`lib/editor`)

편집기의 제품 부품, 수식, 다이어그램, 이모지를 만들면서 정한 것 34가지다. 적은 때는 2026-11-10 23:52 KST다. 설명과 수치는 `docs/spike-editor.md` 10절에, 서버는 이 판을 받아들였다(`docs/contract-pending.md` 1절).

#### 저장 형식

1. 수식 노드의 이름은 `inlineMath`, `blockMath`, 속성은 `latex`. 화면의 표식은 `data-type="inline-math"`·`"block-math"`와 `data-latex`.
   - 왜: 편집기 라이브러리(Tiptap)의 공식 수식 확장이 쓰는 이름과 표식 그대로다. 다른 Tiptap 편집기에서 복사한 수식이 붙여넣기로 읽히고, 뒤에 공식 확장으로 옮겨도 문서가 그대로다.
   - 다른 안: `mathInline`·`mathBlock`, 한 노드에 `display` 속성.
   - 바꾸려면: `src/lib/editor/schema.ts`의 `NODE_SPECS`, `drawing.ts`의 `MATH_SLOTS`. 저장된 문서가 생긴 뒤에는 `body_version`을 올려야 한다.
2. `latex`는 1–4,000자(UTF-16 코드 단위). 빈 수식은 저장하지 않는다.
   - 왜: 수식은 보는 사람의 주 스레드에서 그린다. 4,000자의 가장 느린 수식이 0.2초였다(10절). 여러 줄 정렬 식도 1–2천 자면 충분하다. 빈 수식은 뜻이 없어 편집기가 노드를 지운다.
   - 다른 안: 1,000자(긴 정렬 식이 잘린다), 10,000자(가장 느린 수식이 1초를 넘긴다).
   - 바꾸려면: `schema.ts`의 `MAX_LATEX`. 서버의 한도와 함께 바꾼다.
3. 다이어그램은 새 노드가 아니라 언어가 `mermaid`인 `codeBlock`. 언어 이름은 소문자 그대로만.
   - 왜: 지시대로 허용 목록을 바꾸지 않는다. 대소문자를 구분하는 것은 `language`가 이미 그런 값이고(클래스 이름이 된다) 마크다운의 관례도 소문자다.
   - 다른 안: `Mermaid`, `mmd`도 받기.
   - 바꾸려면: `schema.ts`의 `DIAGRAM_LANGUAGE`, `drawing.ts`의 `DIAGRAM_CODE_SELECTOR`.
4. 그리는 다이어그램 원문의 한도는 20,000자. 넘으면 코드 블록으로만 보인다(문서로는 유효하다).
   - 왜: 라이브러리의 기본 한도는 50,000자다. 그리는 일은 멈출 수 없어서 원문의 길이로 막는다. 간선 500개짜리 흐름도가 1만 자 안팎이다.
   - 다른 안: 50,000자(기본), 5,000자.
   - 바꾸려면: `schema.ts`의 `MAX_DIAGRAM_SOURCE`.

#### 제품 부품 `BodyEditor.svelte`

5. 서식 도구 모음을 부품 안에 두지 않고, 선택 인자 `toolbar`(스니펫)로 받는다. 스니펫은 `{ editor, changes }`를 받는다.
   - 왜: `lib/editor`는 `lib/ui`(버튼)를 가져올 수 없는 층이다. 버튼을 이 층에서 다시 그리면 공용 버튼과 두 벌이 된다. 스파이크 화면이 이 인자로 도구 모음을 그린다.
   - 다른 안: 이 층에서 버튼을 직접 그리기, 도구 모음을 `lib/components`의 별도 부품으로 두기(권장하는 다음 걸음).
   - 바꾸려면: `body-editor.ts`의 `BodyEditorProps.toolbar`, `BodyEditor.svelte`의 `{@render toolbar…}`.
6. 검증에 실패하는 문서는 불러오지 않는다: 편집기는 비고 읽기 전용이 되며 그 사실을 알린다. `onChange`는 불리지 않는다.
   - 왜: 편집기는 모르는 노드를 말없이 버리고 읽는다. 그 상태로 한 글자를 고치면 원래 본문 위에 "고친 추측"이 저장된다. 더 새 판(`body_version`)이 쓴 본문을 옛 클라이언트가 지우는 경우가 바로 이것이다.
   - 다른 안: 읽을 수 있는 만큼만 읽어 편집하게 하기, 호출부에 맡기기.
   - 바꾸려면: `BodyEditor.svelte`의 `loadable`, 문구는 `messages/`의 `editor_body_unreadable`.
7. 선택 인자 셋을 더했다: `label`(글 상자의 접근성 이름), `toolbar`, `onLoad`(문서를 읽은 뒤 편집기가 저장할 모양을 알린다). 내보낸 함수 둘: `storedDoc()`, `focus()`.
   - 왜: 약속한 모양에 필요한 인자는 선택 인자로만 더하라는 지시대로다. `onLoad`는 스파이크 화면과 테스트가 "읽은 것이 준 것과 같다"를 확인하는 데 쓴다. `storedDoc()`은 카드를 닫을 때 늦춘 저장을 바로 내보낼 수 있게 한다.
   - 다른 안: 편집기 인스턴스를 그대로 내주기.
   - 바꾸려면: `body-editor.ts`.
8. `class`는 문자열만 받고 글 상자(`doc-body` 요소)에 붙는다.
   - 왜: 약속한 모양이 `class?: string`이다. `BodyView`가 그 요소에 붙이는 것과 같게 했다.
   - 다른 안: 바깥 틀에 붙이기.
   - 바꾸려면: `BodyEditor.svelte`의 `rootAttributes`.
9. 이미지 파일은 붙여넣기와 끌어 놓기로만 받는다. 올리는 동안은 문서 밖의 자리 표시(장식)를 보이고, 식별자가 오면 `image` 노드를 넣는다. 실패하면 상태 줄에 알리고 문서는 그대로다.
   - 왜: `files.ts`의 전제(올리기가 끝나야 식별자가 있다)대로다. 올리는 중인 것은 저장되지 않는다.
   - 다른 안: 임시 노드를 문서에 넣기.
   - 바꾸려면: `src/lib/editor/uploads.ts`.
10. 멘션 목록은 이름에 친 글자가 든 사람을 8명까지 보인다.
    - 왜: 스파이크의 동작 그대로에 상한만 두었다.

  - 다른 안: `zstd` 명령을 부르기(기기마다 있어야 한다), WebAssembly 패키지(의존성).
  - 바꾸려면: `tools/build/output.ts`의 `compressedForms`.
- **B2.** 수준은 **19.**
  - 왜: 빌드 때 한 번 압축하므로 시간은 문제가 아니다(텍스트 8개 합계 약 0.12초). 20–22("ultra")는 이 크기의 파일에서 얻는 것이 없고(합계가 4바이트 다르다), 큰 파일에서는 `zstd` 콘텐츠 인코딩의 한도인 창 8 MB(RFC 9659)를 넘긴다(17 MB 입력에서 19는 8.0 MB, 20–22는 17 MB).
  - 다른 안: 3(기본값, 58% 더 크다), 22(같은 크기, 큰 파일에서 브라우저가 거절할 수 있다).
  - 바꾸려면: `tools/build/output.ts`의 `ZSTD_LEVEL`.
- **B3.** 프레임이 요구하는 창이 8 MB를 넘으면 빌드가 실패한다.
  - 왜: 넘으면 브라우저가 응답을 버린다. 지금의 파일은 모두 한 덩어리 프레임이라 창이 파일 크기와 같다(가장 큰 것이 187 KB).
  - 다른 안: 검사 없이 수준 19만 믿기.
  - 바꾸려면: `MAX_ZSTD_WINDOW`, `zstdWindowSize`.
- **B4.** 미리 보기 서버가 고르는 순서는 **`br` → `zstd` → `gzip`.**
  - 왜: 한 번 압축해 여러 번 보내는 파일은 바이트가 기준이다. 텍스트 8개 모두 brotli 11이 zstd 19보다 작다(합계 94,910 대 105,453). 그리고 `e2e/shell.spec.ts`가 브라우저에게 `br`이 오는지를 본다(그 브라우저는 `gzip, deflate, br, zstd`를 보낸다).
  - 다른 안: `zstd` 먼저(푸는 속도가 빠르다. 이 크기에서는 차이가 작고 11% 더 보낸다), 받는 쪽이 허락한 것 가운데 가장 작은 파일.
  - 바꾸려면: `tools/build/encodings.ts`의 `ENCODINGS` 배열의 순서 하나. 서버의 순서는 서버 쪽이 정한다.
- **B5.** `Accept-Encoding`을 낱말로 읽고 `q=0`은 거절로 본다.
  - 왜: 전에는 글자열에 `br`이 들어 있는지만 봤다. `zstd;q=0`을 보낸 쪽에 `.zst`를 보내면 안 된다.
  - 다른 안: 받는 쪽의 `q` 값 순서까지 따르기(브라우저는 `q`를 보내지 않는다).
  - 바꾸려면: `acceptsEncoding`.
- **B6.** `tools/serve.ts`도 파일 옆에 압축본이 있으면 같은 규칙으로 보낸다.
  - 왜: 지시. 그 서버가 지금 보여 주는 폴더(스파이크, Storybook)에는 압축본이 없어 동작이 달라지지 않는다. `dist`를 올리면 쓰인다.

  - 바꾸려면: `tools/serve.ts`의 `chooseEncoding` 호출.

  - 카드를 다른 열로 옮기면 뷰 패치 하나와 카드 패치(연결 12)가 따로 간다. 한쪽만 실패하면 저절로 되돌리지 않는다: 실패한 쪽만 화면에서 되돌아가고 알림이 뜨며, 성공한 쪽은 서버에 남고 실행 취소에도 남지 않는다. 묶음 패치(`boards-and-blocks`, A7)로 둘을 함께 보내면 없어지는 틈이다. 쓰지 않은 까닭: 그 라우트의 모양을 화면의 두 패치에 맞추는 일이 이 묶음의 범위를 넘는다.
  - 바꾸려면: `lib/api/backend.ts`의 `patchView`.

- **연결 14.** 실시간 변경은 페이지에 WebSocket 하나다(`lib/api/live.ts`의 `LiveChanges`). 첫 구독(`watchContainer`/`watchSelf`)이 같은 출처의 `{base}/ws`를 열고(쿠키가 저절로 실린다) 팀을 구독한다. 마지막 구독이 끝나면 닫는다.
  - 메시지는 화면의 변경(`Change`)으로 바꿔 그 보드의 구독자에게, 보드 자체의 변경은 읽는 사람 자신의 구독자에게도 준다. 구성원 메시지는 그 보드를 보는 곳이 있을 때만 구성원 전부를 다시 읽는다(나중에 시작한 읽기만 알린다. 403·404면 그 보드는 없어진 것으로). 구성원과 카테고리의 메시지는 0.2초 동안 모아 사이드바(보드 목록과 카테고리)를 한 번 다시 읽게 한다: 보드에 더해지거나 빠질 때 보드의 메시지가 따로 오지 않고, 카테고리 메시지는 조각뿐이다. 템플릿 보드는 사이드바에 넣지 않는다.
  - 연결이 끊기면 0.5, 1, 2, 5, 10, 30초(그 뒤로 30초)를 기다려 다시 연다. 기다림은 연결이 10초 버틴 뒤에야 처음으로 돌아간다. 브라우저가 다시 온라인이 되면, 그리고 로그인하면(`restart`, 쿠키가 바뀐다) 곧바로 연다.
  - 다시 열리면 모든 구독자에게 새 변경 `resync`를 준다. 열린 보드는 화면을 둔 채 보드·뷰·카드·구성원을 다시 읽어 보이는 것과 합친다(`state/write.ts`의 `reread`: 쓰는 중인 것과 읽는 동안 온 것은 그대로, 읽기 시작할 때 있었고 읽은 것에 없는 것은 지운다. 겹친 읽기는 나중 것만). 열린 카드는 댓글·첨부를 다시 읽고, 지워졌으면 "없음"이 된다. 작업 공간은 보드 목록과 카테고리를 다시 읽는다. 경계(`Change`)에 `resync`를 더했다. 메모리 구현은 보내지 않는다.
  - 구독에는 답이 없어, 다시 연결한 직후의 아주 짧은 틈(구독을 보낸 뒤 서버가 받기 전)의 쓰기는 놓칠 수 있다.
  - 왜: 서버는 놓친 것을 다시 보내지 않고 순번도 없다(G6). 무엇을 놓쳤는지 모르니 보이는 것을 다시 읽는다.
  - 다른 안: 다시 열릴 때 페이지를 새로 고치기(편집 중인 것을 잃는다) / 보드마다 연결.
  - 바꾸려면: `lib/api/live.ts`, `state/board.svelte.ts`와 `workspace.svelte.ts`의 `#refresh`, `state/card.svelte.ts`의 `refresh`.

- **연결 15.** 블록 지우기는 `deleteBlock`(서버의 휴지통으로, 아래 것과 함께, 204), 되살리기는 `undeleteBlock`(함께 간 것과 함께)이다. 화면에서 되살리기는 실행 취소와 휴지통 화면(`TrashDialog.svelte`)이다. 되살린 카드는 화면의 저장소가 다시 읽어 보인다(`BoardStore.restoreCard`).
  - 서버는 되살린 블록 하나만 알린다. 다른 사람의 화면에는 카드가 돌아오고, 그 댓글·첨부는 카드를 열 때 읽힌다.
  - 같은 두 조작으로 뷰, 댓글, 첨부를 지우고 되살리며, 만든 카드를 실행 취소하면 지운다. 실서버 종단 테스트는 카드만 본다.
  - 되살린 뒤 카드를 다시 읽지 못해도 실행 취소는 된 것으로 친다(두 번 되살릴 수 없다). 만든 것을 실행 취소하며 지우는데 다른 사람이 이미 지웠으면(404) 지운 것으로 친다.
  - 다른 사람이 열어 둔 카드가 지워졌다가 되살아나면 "없음"이 풀린다.
  - 바꾸려면: `lib/api/backend.ts`의 `deleteBlock`, `restoreBlock`.

- **연결 16.** 본문 검증기(`editor/schema.ts`의 `validateDoc`)는 서버의 허용 목록을 따른다. 공유 벡터 `contracts/body-vectors.json`을 `tests/editor/body-vectors.test.ts`가 읽는다. 그래서 멘션의 `userId`는 소문자 UUID이고, U+0000과 `content`·`marks`의 `null`은 거절한다. 그리기(`renderBody`)만 `shown`으로 느슨하다: 빈 `userId`(익명 독자에게 오는 멘션)와 U+0000을 그린다. 편집기는 쓰기의 규칙으로 싣는다.

- **연결 17.** 댓글은 `createBlocks`로(`type: comment`, 카드가 부모, 글이 `body`) 만들고, `patchBlock`의 `body`와 `readAt`으로 고친다(답이 204라 다시 읽는다). 고치기 단추는 보드를 고칠 수 있는 사람의 자기 댓글에만 있고, 글자만 든 문단으로 된 댓글만 고친다(댓글 칸이 그 밖의 것을 담지 못한다). 낡은 판(409)이면 댓글을 다시 읽고 쓴 글은 칸에 남긴다.

- **연결 18.** 파일은 크기에 상관없이 올리기 세션으로 올린다(`api/upload.ts`): `createUpload`, 부분마다 `putUploadPart`(`Content-Digest`의 SHA-256), `completeUpload`. 부분 크기는 서버의 답을 따르고, 답이 없거나 500인 부분은 세 번까지 다시 보낸다. 그만두거나 실패하면 `deleteUpload`. 서버의 한도(`getClientConfig`의 `maxFileBytes`)를 넘는 파일은 보내기 전에 413으로 거절한다. 첨부는 `createBlocks`의 `attachment` 블록이고 `fields`에 `fileId`, `size`, `contentType`을 둔다.

- **연결 19.** 팀의 열린 보드(`O`)를 구성원이 아닌 사람이 열면(보드는 읽히고 뷰·카드·구성원은 403) 보드의 제목과 설명, "이 보드에 참여" 단추를 보인다(사용자 결정). 누르면 `joinContainer`로 참여하고 보드를 다시 읽는다. 열기만으로는 참여하지 않는다.
